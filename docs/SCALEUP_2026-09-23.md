## Context

The method (fence → gate → read) and every diagnostic so far live on one backbone
(Qwen2.5-VL-7B) and one benchmark (official MMReD, synthetic renders). Tal wants the results to be
trustworthy beyond that pair: add **MINERVA** and **HERBench lite_v2** (real video, 5-way MCQ,
per-question evidence timestamps) and **two backbones from different model families**, without
forking the code per dataset or per model. Order chosen by Tal: (1) frozen baselines on each new
dataset, (2) **the fence's per-block evidence classification per task** — is "this block contains
an evidence frame" linearly present in the block's slot state? — as the first test, *before* the
full method, (3) then the method (gate + read) where stage 2 says a gate is learnable.

Facts that shape the design (all verified this session; sources in the appendix):

- `core/` today: rows are bare dicts; block discovery, slot, position reset (`(3,1,L)` M-RoPE),
  delimiters (`<|vision_start|>/<|vision_end|>/<|image_pad|>`, `<|im_end|>` as a literal in five
  scripts), evidence labels (`evidence_frames` computed from symbolic states), gold recomputation as

  16-threshold are all MMReD- or Qwen-specific. The one registry pattern in the repo is
  `experiments/_port_check.py:PORT_CHECKS`. The `ARMS` vocabulary is defined four times.
- HERBench lite_v2 (HF `DanBenAmi/HERBench`, config `lite_v2`): 1,971 questions, 68 videos, 12 tasks,
  5-way MCQ (letter prior skewed: C 26 %), **explicit `metadata_json` evidence timestamps for 11/12
  tasks** (RLPC = "All"), videos shipped as `videos.tar.part.00–03` (34.3 GB; HD-EPIC 1408², 30 fps,
  up to 56 min; WildTrack/PersonPath22/trailers 1080p). No train split. Official protocol: 16 uniform
  frames; Qwen2.5-VL-7B 35.9 % on the full set; counting (AC) at chance for every published model.
  The project already used HERBench-lite AC in July (144 questions; frozen own-answer EM 0.049,
  look-again judge AUROC 0.83; `docs/archive/RESULTS_pre_fencing.md:2342-2430`); those videos are gone.
- MINERVA (Nagrani et al., ICCV 2025, arXiv 2505.00681): ~1,285–1,341 questions, ~190 YouTube videos
  (2–100 min, mean 12), 5-way MCQ, 13 skills (Counting 263, Event Occurrence 188, Temporal 121,

  Only Qwen2.5-VL-7B weights exist on disk (home cache 140/300 G used); `/rg` is 97 % full (138 G free).

## Decisions taken this session (Tal, via AskUserQuestion)

- Backbones: **InternVL3.5-8B-HF + Gemma-3-12B-it** (§4); no closed-model API rows — published
  Gemini / GPT numbers are quoted.
- Stage 2 = per-block evidence classification (gate_capture + gate_fit per task), run before the method.
- Installs Tal runs into `.venv`: `av` (PyAV) and `pylance`. No yt-dlp.
- Raw videos to `/rg/shocher_prj/lab_data/{herbench,minerva}/videos/`, streamed (no joined tar copy),
  **kept** after frame extraction (~43 GB of the 138 G free; `cleanup_2026-09-21.sh` is Tal's call).
- Stage 1–3 row budget: 50 rows per task (~580 HERBench, ~470 MINERVA), stratified by answer letter;
  the official 16-frame comparability row runs on all rows.
- Every dataset is materialised into ONE on-disk layout by a prepare script, so the loader,
  `stage_split`, and every experiment are shared (no dataset-specific loaders in experiments).
- The "N axis" on real video is a **frame-sampling protocol**, not a dataset config. Two protocols
  (§3.3): `planted` (evidence frames at annotated times + uniform fillers to N — the thesis's k-of-N
  design, HERBench's own "oracle frames" setting) is the instrument protocol; `uniform` (the
  benchmarks' official sampling) is the comparability row only.
- MMReD stays the anchor: a new backbone is validated on MMReD first; a new dataset is validated on
  Qwen2.5-VL-7B first; cross cells come last (diagonal-first schedule, §5).

## 1. Architecture: two seams, one registry each

### 1.1 Dataset seam — `core/data/`

```
core/data/__init__.py   DATASETS = {"mmred": MMReD, "herbench": HERBench, "minerva": Minerva}; get_dataset(name)
core/data/base.py       Sample (frozen dataclass) + DatasetSpec (the contract every dataset implements)
core/data/mmred.py      thin adapter over the EXISTING core.mmred (no function moves; tests untouched)
core/data/videoqa.py    VideoMCQ: the shared real-video implementation (HERBench + MINERVA differ only in
                        prep-time parsing, task lists and the official prompt suffix)
core/data/mcq.py        letter parsing + matching (ports of the legacy readers), option formatting
```

`Sample` fields: `qid, question (bare official text), answer (canonical string: MMReD value or MCQ
letter), qtype, frame_paths: Tuple[Path,...] (resolved at load, in temporal order), evidence:
Optional[FrozenSet[int]] (per-frame labels at THIS N; None = unknown), group (leakage key: qid for
MMReD, video_id for video), meta (raw row: options, states, timestamps…)`.

`DatasetSpec` contract (one method each; MMReD's implementation just delegates to `core.mmred` /
`core.prompt`): `qtypes`, `numeric_qtypes`, `has_train`, `supports_counterfactual` (probe_hahn:
MMReD only), `split_name(protocol, N, split)` (MMReD: `seq_len_8_test`; video: `planted_N8_test`),
`load(root, protocol, N, split, qtypes) -> List[Sample]`, `frames(sample)`, `system_prompt`,
`question_text(sample)` (MMReD: bare question; MCQ: question + options + the benchmark's own
instruction line), `answer_target(sample)`, `parse(raw)`, `match(pred, sample)`, `verify(sample)`
(MMReD: recompute == published; video: True), `stratify_key(sample)`, `report_extras(samples, preds)`
(MMReD: the ≤16/>16 split; video: coverage = share of samples with ≥1 evidence frame, k_visible
histogram, letter-prior baseline).

What changes in existing modules: `core/prompt.py::build_messages` gains `system_prompt=SYSTEM_PROMPT`
(default = today's behaviour; `tests/test_prompt.py` stays green); `core/mmred.py` unchanged;
`core/metrics.py::em_table` keys by `sample.qtype` (already does).

### 1.2 Backbone seam — `core/backbones/`

```
core/backbones/__init__.py  BACKBONES = {"qwen2.5-vl-7b": ..., "internvl3.5-8b": ..., "gemma-3-12b": ...}; get_backbone(name)
core/backbones/base.py      BackboneSpec (frozen dataclass) + the generic functions below
core/backbones/qwen2_5_vl.py, internvl.py, gemma3.py   (one spec each; ~30 lines of data + any per-model hook)
```

`BackboneSpec`: `name, model_id, family, lora_targets, delimiters (start: Optional[str], end:
Optional[str], pad: str, turn_end: str), block_rule ("pair" = [start_i, end_i+1) as today; "pad_run"
= run of pad tokens plus the adjacent end token, for models without a start token), rope ("mrope" |
"1d"), image_attention ("causal" | "bidirectional"), layer_types (None, or per-layer
full/sliding + window — Gemma 3), probe_layers (default capture depths as fractions of depth,
so `--hs-layers` stays comparable across models), tokens_per_frame_512 (pinned by a tokenizer
test), processor_kwargs (tiling OFF: one tile per frame — e.g. InternVL `crop_to_patches=False`,
Idefics3 `do_image_splitting=False`; Qwen: none), passthrough_keys (every non-text input the
forward needs re-passed under the fence: Qwen `pixel_values, image_grid_thw`; Mistral3 adds
`image_sizes`; Gemma3 adds `token_type_ids`)`.

Generic functions (in `base.py`, taking the spec): `load_runtime(spec, ...)` (today's
`core.model.load_runtime` + spec.processor_kwargs; `core.model.load_runtime()` becomes a wrapper
that resolves the Qwen spec so nothing else changes), `special_ids(spec, tokenizer)` (adds
`turn_end`, removing the five `<|im_end|>` literals), `blocks(spec, ids, layout)` (today's
`layout_blocks` with the two block rules), `slot(block) = block_end − 1` (for Qwen this IS
`<|vision_end|>`; for pad-run models it is the last image/end token — `test_slots` keeps
"slot = last token of its block"), `base_positions(spec, model, inputs)` (mrope: `get_rope_index`;
1d: `arange`), `attention_dims(spec, model)` (`mrope_section` only when rope == mrope).

### 1.3 The fence, generalised (`core/fence.py`)

- `reset_positions(base_pos, blocks, fin_start)`: same arithmetic over any leading shape
  (`(3,1,L)` and `(1,L)`), shift read from the first row; `test_legacy_parity` stays bit-for-bit.
- `build_block_mask(seq, blocks, hide_cols, *, bidir_spans=())`: unchanged by default; `bidir_spans`
  (each block's image-token run) opens the full square inside a block for bidirectional-image
  models. New test: within-block image square is all-zero, everything else identical to today.
- `sliding_window_mask(mask, positions, window)` for models with local layers: the window is applied
  in **reset-position space** (the distance the model actually sees), ANDed with the block mask, and
  `FenceHooks` accepts either one mask (today) or `{"full_attention": m, "sliding_attention": m_w}`
  keyed by each layer's `attention_type`. With prefix + one block ≈ 100 + 258 tokens < 1024 the
  window never cuts inside a fenced block; the deviation is documented with the arm.
- `fenced_setup(inputs, blocks, fin, keep, backbone, model)` replaces the `rope_fn` argument;
  `greedy_decode` re-passes `spec.passthrough_keys` instead of the two Qwen names.
- Everything above keeps the current Qwen code path byte-identical (parity test + the D4/C1 anchors
  re-run once on Qwen after the refactor: same numbers = the refactor is proven).

### 1.4 Experiments and wrappers

- `evaluate.py`, `gate_capture.py`, `gate_fit.py`, `train.py`, `probe_attention.py`: add
  `--dataset {mmred,herbench,minerva}` (default mmred) and `--backbone` (default qwen2.5-vl-7b);
  `--config` keeps MMReD semantics; video datasets take `--protocol {planted,uniform} --n-frames N`.
  `--qtypes` choices come from the dataset spec. `recompute_answer`/`evidence_frames` calls become
  `spec.verify(sample)` / `sample.evidence`. The `ARMS` table moves to ONE place
  (`core/data/base.py` or `experiments/_arms.py`) — `plain, qfirst, fenced_qlast, fenced_qfirst,
  gated`. `probe_hahn.py` refuses `--dataset != mmred` (counterfactual renders), by design.
- `gate_fit.py`: hold out by `group` (video_id for video — questions of one video share frames; a
  qid split would leak frame identity), report AUC + balanced accuracy + per-class accuracy
  (memory: probe-family artifact), per qtype, and the N≤16 → N≥32 transfer table as in D4.
- New `experiments/prepare_video.py --dataset {herbench,minerva}`: annotation download →
  `json/<split>.json` rows (qid, video_id, question, options, answer letter, qtype, evidence

  512 px, JPEG q95, `pool/<video_id>/frame_%04d.jpg` + `times.json`) → per-question **evidence
  frames** (`evidence/<qid>/frame_%04d.jpg` + times) → `pool.tar`, `evidence.tar` for `stage_split`.
  PyAV seek-to-timestamp decoding (the legacy recipe `prep_ac_frames.py:36-55`), Agg-free, CPU-only,
  resumable, `SLURM_CPUS_PER_TASK` worker cap. Run under `4h_0g`.
- `sbatch/`: wrappers gain `DATASET`, `BACKBONE`, `PROTOCOL`, `N` env knobs; `stage_split` takes
  `<dataset> <tarball…>` (MMReD: `images/<split>.tar` as today; video: `pool.tar evidence.tar`).
  A wave script `sbatch/scaleup_submit.sh <stage> <dataset> <backbone>` records job ids in
  `outputs/scaleup/jobs.tsv` (the `diag_submit_tier0.sh` pattern).
- Run dirs: `outputs/scaleup/<dataset>/<backbone>/<stage>/<cell>/<stamp>_<job>/`; group docs
  `outputs/scaleup/{CAMPAIGN_BRIEF,STATE,INDEX}.md` (git-tracked).

## 2. HERBench lite_v2 — prep design

- Rows: `data/herbench_annotations_lite_v2.json` (2.6 MB). Per task the evidence field differs
  (verified schema): TSO/SVA `timestamps` (4 ranges), FAM/FOM `required_timestamps` (4 points),
  ASII (5 points), AC (one point per counted occurrence; **lite_v2 AC true_count is 1 for 115/144**),

  every frame; excluded from the gate cells, kept for baselines). Three timestamp formats
  (`MM:SS.s-MM:SS.s`, `M:SS:mmm`, `HH:MM:SS.mmm - …`) parsed per source with a fixture test.
- Tasks → our axes: aggregation = AC, RLPC, MEGL, MPDR, FAM, FOM; order = TSO, ASII, SVA;
  needle = AGAR, AGBI, AGLT. `--qtypes` = the 12 task codes.
- Videos: `videos.tar.part.00–03` streamed through `tar -x` (no joined copy; 34.3 GB on
  `/rg/shocher_prj/lab_data/herbench/lite_v2/videos/`), then pools + evidence frames (~1.5 GB).
  Whether the mp4s stay after extraction is Tal's call (open question below).
- Official comparability row: `uniform`, N = 16, frames-first, the official prompt suffix
  ("Please respond with only the correct answer letter (A, B, C, D, or E) …"), letter regex —
  reproduce the published Qwen2.5-VL-7B band (35.9 % full set / ~31 % README; lite_v2 third-party

- Rows: DeepMind `minerva.json` (1,285 Q) ∪ lmms mirror (1,341 Q; 1,278 shared); use the lmms
  `minerva.json` as the row source since its videos are what we can fetch (8.85 GB Lance blobs,

- Videos: `lance` (`pylance`) read of `hf://datasets/lmms-lab-eval/minerva/data/train.lance` →

### 3.3 The N axis on real video (both datasets)

- `planted_N<k>`: the question's evidence frames (one per point at t + 0.3 s, one per range at its
  midpoint — the legacy convention; ranges longer than 2× the fill spacing contribute more frames,
  capped so k ≤ N/2) plus fillers from the pool, spaced ≥ 5 s from every evidence time, seed 0,
  all sorted by time. N ∈ {8, 16, 32, 64, 128}; `evidence` = exact. This is the k-of-N design and
  makes stage 2 well-posed. Questions whose evidence count exceeds N/2 are skipped and counted.
- `uniform_N<k>`: the first k of the pool's 128 (nested); `evidence[t]` = frame time within
  ±(half the sampling interval, capped at 2 s) of a point, or inside a range. Coverage
  (≥1 evidence frame visible) is reported per cell — under uniform sampling most point events are
  unseen at N ≤ 32 (the MLVU finding: 35 % zero-evidence at N = 32), so this protocol is for the
  comparability row, not for the gate.

## 4. Backbones — the pick

Constraints that decide it: dense (bitsandbytes cannot quantize packed MoE experts → Kimi-VL,
Llama-4-Scout, Aria, GLM-4.5V, InternVL3.5-30B-A3B, Qwen3-VL-30B-A3B are out), native class in
transformers 4.57.6 (no remote code, so hooks/PEFT/sdpa behave), image tokens **inside** the LM
sequence (cross-attention Llama-3.2-Vision cannot be fenced), a per-image end marker or a
contiguous pad run, ≤ ~380 LM tokens per 512 px frame (N = 128 ≤ ~49 K tokens), fits 40 GB nf4
mask-free (masked N = 128 on the h200 as today), and — Tal's choice — **an LM lineage that is not Qwen**.

The survey's decisive fact: InternVL3.5-8B, LLaVA-OneVision-1.5-8B, Ovis2.5-9B, MiniCPM-V 4.5,
Molmo2-8B, Keye-VL-1.5 and Step3-VL-10B all run **Qwen3-8B** as the decoder; Qwen3-VL-8B is the
same family by construction; MiMo-VL is Qwen2.5-VL wiring with a different LM. The dense,
native, non-Qwen LMs that fit are Gemma 3, Mistral Small 3.x, GLM-4.1V-9B (3D-RoPE, Thinking
model), Phi-4-multimodal (vision is itself a LoRA on the LM), SmolVLM2 (2 B, too weak).

**Pick (Tal, 2026-09-23): InternVL3.5-8B-HF + Gemma-3-12B-it** — models reviewers of video
benchmarks recognise (both lineages are in the HERBench table), InternVL as the engineering-light
"different VL wiring" point (labelled "Qwen3-8B LM" in every table), Gemma as the non-Qwen LM family
with a different attention regime. Closed models (Gemini Flash, GPT-4o) are **not** run: they expose
no masks, positions or hidden states, so they cannot be fenced or probed; their published HERBench /
MINERVA numbers are quoted in the comparison table instead (Tal, same day). Fallbacks: Gemma 4-bit
smoke fails on bnb 0.48.2 → Mistral-Small-3.2-24B (plain causal, Apache-2.0) or GLM-4.1V-9B-Base;
Qwen3-VL-8B stays an optional same-family control, not one of the two.

Registry keys: `qwen2.5-vl-7b` (default), `internvl3.5-8b`, `gemma-3-12b`.

InternVL3.5-8B-HF specifics: `OpenGVLab/InternVL3_5-8B-HF`, native `InternVLForConditionalGeneration`
(no remote code), `crop_to_patches=False` → exactly one 448² tile = 256 `<IMG_CONTEXT>` tokens per
frame (the processor resizes 512 → 448; documented as the model's own preprocessing, not ours);
delimiters `<img>` … `</img>` (pair rule, slot = `</img>`); plain 1-D RoPE → the reset is a 1-D
reset; the HF processor prefixes multi-image turns with `Frame{i}: ` text — the tokenizer test pins
whether that text lands inside or outside the block (it must be outside, in the prefix/between
blocks, or the block rule is extended as for `replica`); known 4.54.1 inference freeze (#39872) →
smoke on 4.57.6 first; V2PE (variable visual position increments) is not exposed by the HF port —
use the checkpoint's plain positions. Weights ≈ 17 GB bf16 → home cache (160 G free).

Gemma-3-12B-it specifics: gated repo — Tal accepts the license on HF before the download (≈ 24 GB
bf16 → home cache); `Gemma3ForConditionalGeneration` native; `token_type_ids` must be passed through
(its own mask builder needs them on mask-free arms); mask injection under the fence is a dict keyed
by `attention_type` (§1.3); pan-and-scan stays off (default); bf16 only (fp16 NaNs in the vision
tower); the day-1 smoke is `--limit 5` frozen generate at N = 8 on `2h_2g` to clear the bnb 0.48.2
4-bit report (#1794) before anything else is scheduled on it.

Gemma-3 caveat to carry into every Gemma row: its own masks give 40 of 48 layers a 1024-token
window by index, so on an unfenced 128-frame prompt only the 8 global layers see the question
from most frames; under the fence (§1.3, window in reset-position space) every layer sees
prefix + own block. That is the fence doing its job, but the Gemma "plain" baseline is a
different regime from Qwen's and must be described as such, never pooled.

# Addendum 2026-09-29 — what the first HERBench wave got wrong, and the corrected protocol (Tal: "do all those")

**Found.** (1) Frames were stored at 512 px on the long side. The benchmark's own frame-based evaluation
(`HERBench/evaluation/model_wrappers/{base_vlm,qwenvl2_5_7b}.py`) decodes frames with OpenCV at the video's
own resolution and passes them unresized; Qwen's processor default (`max_pixels` 12,845,056) then shows a
1920x1080 frame as 1932x1092 = **2,691 tokens**, a 1408x1408 frame as 2,500, a 1280x720 frame as 1,196. We
showed 180 / 324 / 180. The `360*420` cap in their wrapper belongs to the separate direct-video path.
(2) Almost every cell used the `planted` protocol, which uses the annotation to choose frames. (3) The dense
fenced path holds all N frames in one sequence, so it is bound by the same total-token limit as the unfenced
model and cannot test the fence where it should matter (many frames at full resolution).

**Decided.**
1. `uniform` sampling (the benchmarks' own) is the PRIMARY protocol on HERBench and MINERVA. `isolated` /
   `planted` stay as labelled diagnostics (they separate "the evidence was never sampled" from "seen and failed").
2. Frames are stored at the video's own resolution (frame set `native`: `pool_native/`, `evidence_native/`;
   the 512 px set stays on disk as frame set `512` so the 09-28 run dirs remain reproducible). The resolution
   the MODEL sees is set per run by the processor's own `max_pixels` knob (`--max-pixels`, 0 = default) and is
   stamped on every report and run dir (`s1_eval/<frame set>[_mp<cap>]/...`).
3. The batched fenced path is built (`core/fastpath.py`, `--fast`): prefix once, blocks as batch rows over the
   expanded prefix cache with block-0 positions, slot read per row, then the read over prefix + KEPT blocks'
   caches and cached greedy decoding. No mask. Parity with the dense path: `tests/test_fastpath.py` (tiny
   random Qwen2.5-VL, float32: slot states 1e-8, logits 3e-7, identical tokens; gated / ungated, both layouts,
   chunked) + the GPU parity jobs under `outputs/scaleup/mmred/qwen2.5-vl-7b/s0_proof/fastpath/`.
   Scope: causal image attention + global layers (Qwen2.5-VL, InternVL3.5). Gemma 3 stays on the masked path.

**Token budget (Qwen2.5-VL, one 1080p frame):** uncapped 2,691 · cap 1,003,520 px -> 1,222 · cap 151,200 px -> 180.
Unfenced runs must fit N x tokens in one context (about 15 / 32 / 220 frames in 40 K tokens); the batched
fenced path encodes any N and its read sees prefix + k kept frames.

**Status of the 09-28/29 numbers.** Refactor proof and MMReD: unaffected. HERBench at the 512 px set
(comparability row 0.461, planted / isolated ladders, probe tables): valid as "512 px" rows, NOT comparable to
the paper and NOT evidence about perception; every table carries the frame set. To be re-measured at native.

**InternVL3.5 runs in non-thinking mode (Tal, 2026-09-29).** Its Qwen3 language model opens a `<think>` block on most
MMReD rows and spends the 24-token answer budget inside it (smoke 164447: 7/12 rows). The spec pre-fills the empty
think block `<think>\n\n</think>\n\n` after the generation prompt (`BackboneSpec.assistant_prefix`), the same for every
arm. Reason: under the fence each generated token is a forward pass, so a reasoning budget of hundreds of tokens is not
affordable, and the short-answer protocol is what the other backbones run. Every InternVL row is labelled
"non-thinking".
