Why the count drowns: the d′ theory of aggregation failure

Vision-language models see every frame yet cannot count across them. This page builds the explanation from scratch — two Gaussian clouds and one number, d′ — derives a zero-free-parameter law for the failure, and then shows the experiments that confirm it, causally, inside a frozen Qwen2.5-VL-7B.

Executive summary

  • The phenomenon. Frozen Qwen2.5-VL answers "how many frames was character C in room R?" at ~85% for 1–2 frames but ~20–30% at 8 — while a linear probe reads the per-frame evidence at 0.95+. Perception is fine; combination fails.
  • The theory. Each frame's message is a point in one of two Gaussian clouds (evidence / non-evidence) with whitened separation d′ ≈ 3.4. Any linear pooling keeps the per-count gap fixed while noise accumulates as √N, so the best possible readout of the pooled state is 2Φ(d′/(2√N)) − 1 — two measured parameters, zero fitted ones. At N=8 that is 0.45–0.51 (interior-only vs uniform-mixture bounds); measured: 0.45–0.47.
  • The receipts. The formula predicts the measured decode ceiling across 20+ regimes (N-sweep predicted .85/.66/.58/.50 vs measured .85/.65/.59/.47), including at the deployed carrier (.375 vs .363). Causal interventions confirm the channel is load-bearing (scrubbing it collapses the model into undercounting; scrubbing a random axis does nothing) and locate the residual wall in the readout: amplifying the count signal ×64 makes it 0.78-decodable at the output position while the frozen head stays at 0.13.
  • The consequence. Nothing placed after pooling can help (sufficiency — measured: MLP never beats linear, 21/21 regimes). Fixes must gate per frame before an unnormalized sum and read the tally directly — the DeepSets/Σσ family, which measured 0.82–1.0 with count extrapolation.

The whole argument in sixty seconds — with exactly four lines of math

The picture. Think of election night in a strange county. Every frame mails in a ballot. The mailroom (attention) has a rule: however many ballots arrive, the pile must always weigh the same — so with more ballots, each one is shrunk before it lands (softmax weights sum to 1). The running total isn't written down as a number; it's stored as the position of an analog needle (a direction in a 3,584-dimensional vector). Every ballot arrives slightly smudged (noise), and the smudges never cancel exactly. And at the end of the night, the announcer reads the needle from the wrong angle.

The four lines. Each frame's ballot is

mk = μ + ek·δ + εk   (shared content + "yes/no" vote along one direction + smudge)

Pool N of them and the votes add like a ruler but the smudges add like a drunk's walk:

S = N·μ + g·δ + Σε,    signal step = ‖δ‖ (fixed),  blur = σ√N (grows)

so the ability to tell g from g+1 shrinks as

separation = d′ / √N,    P(exact) = 2Φ(d′ / 2√N) − 1

— and if the mailroom averages instead of sums (divide by N), then "2 of 4" and "4 of 8" land the needle on the same spot, noiselessly:

mean: gap = ‖δ‖/N → counts collide across lengths; only the fraction g/N survives

The intuitive fix, in one sentence. Count votes; don't average opinions. Read each ballot on its own, while its signal is still strong (per-frame d′ ≈ 3–7, an easy yes/no), turn it into a hard decision, and add the decisions as integers — integers don't blur, a tally of 1+1+1 has no √N, no divisor, and no needle to misread. Everything in Part IV (the tally register) is this sentence made mechanical: gate per frame → add without normalizing → read the number directly. The reason it extrapolates to any length is that nothing in "1+1+1" changes when N grows.

Part I — The theory

1What breaks, and what gets pooled

The task: 8 frames, one question — "how many frames was character C in room R?" (answer 0–8). The model's accuracy collapses from ~85% at 1–2 frames to ~20–30% at 8, and the same length-collapse appears on two other aggregation tasks (distinct-rooms, co-occupancy). Yet a linear probe reads "is C in R in this frame?" from the model's own representations at 0.95+. Every ingredient is present; combining them is what fails. This page is about why — stated precisely enough to predict the failure's exact size. One disambiguation to carry through the whole page: the law predicts the ceiling of what any readout could extract from the pooled representation (≈0.47 at N=8) — the model itself does even worse than its own ceiling (~0.21), and the gap between the two is a second, separate wall (the readout, C6). Ceiling first; the model's extra deficit after.

Fix one sample. Somewhere inside the model, each frame k contributes one vector mk ∈ ℝd (d = 3584) to the position that aggregates. For all of Part I you only need the informal reading: mk is "what frame k tells the question" — one vector per frame, extracted from the model's own attention traffic; the exact definition (which token receives it, which layer, the formula) is Part II's job. One clarification up front: there are several question tokens receiving messages, so mk is defined per (carrier token, layer) — each locus gets its own decomposition and its own d′. Headline numbers use the peak carrier (the room token, L16); the character token, the last token, and the all-question block each have their own, weaker, decomposition, and the same law holds at every one of them (C1). Nothing below depends on having picked "the one true" carrier. Every frame is one of two kinds — evidence or non-evidence — so the honest minimal model is two labeled Gaussian clouds:

mk = μ + ek·δ + εk,   εk ~ 𝒩(0, Σ),   answer g = Σek ek = 1 if frame k is evidence, else 0 · μ = shared "a-frame-is-here" component · δ = arrow from the non-evidence mean to the evidence mean · ε = everything else the frame encodes
δ = μE − μN = E[m | evidence] − E[m | non-evidence] the evidence direction: average evidence message minus average non-evidence message

δ is not mystical — it is literally the difference of the two class means. Its geometric meaning is the whole game: adding one evidence frame moves the pooled vector by exactly one δ, so the count is encoded as how many δ-steps the pool has taken. Two measured facts set the difficulty: ‖δ‖ is ~1% of ‖μ‖ (the count rides far below the generic frame content), and ε is large — each frame also carries rooms, characters, layout. This two-cloud form is the model underneath Fisher's linear discriminant (1936) and sixty years of signal detection theory (Green & Swets 1966), and — Part III, C4 — its assumptions are checked, not assumed.

2A linear probe is an axis, and d′ is its one number

A linear probe is a direction w plus a cutoff: compute the scalar p = wᵀm, say "evidence" if it clears the cutoff. Geometrically it drops every point perpendicularly onto the line through w — the reading axis — and keeps only where it lands. After projection you have two 1-D Gaussians, and every symbol has a concrete definition:

a = E[wᵀm | non-evid] = wᵀμ,   b = E[wᵀm | evid] = wᵀ(μ+δ),   σw = std(wᵀε) = √(wᵀΣw) a, b = the two bump centers · σw = the within-class spread of the projected scores along this axis (empirically: ½(stdE + stdN) of held-out projections)
What exactly is "the noise" — computed, with a five-number example

Nothing here is random in the sensor sense — the forward pass is deterministic. "Noise" means within-class content variability: a hundred evidence frames all have C in R, but everything else differs (where the other characters are, which rooms are occupied), and all of that is irrelevant to the label — so to the count-reader it is noise. Computation: (1) from TRAIN frames, class means μ̂E, μ̂N; each frame's noise vector is the residual against its own class, ε̂k = mk − μ̂class(k) — subtracting the class mean removes μ and δ, so what survives is by construction the label-independent content. (2) A 3584-dim residual has no single "size"; noise gets a scalar only relative to a reading axis: project held-out frames, pk = wᵀmk, and within one class those scalars scatter around the class's mean projection. "std over pk" = the standard deviation of that list of scalars, one class at a time. (3) σw = ½(stdE + stdN) — the ½ is nothing deep: it is the plain average of the two classes' spreads (the pooling licensed by the equal-covariance check, std-ratio 0.89–0.92; population version: σw² = wᵀΣw for unit w). Worked example: evidence projections 5.1, 4.2, 6.0, 4.7, 5.5 → mean 5.1, std 0.6; non-evidence 2.2, 3.4, 2.7, 3.0, 2.9 → mean 2.8, std 0.4. Then σw = ½(0.6+0.4) = 0.5, gap = 2.3, d′ = 4.6. Two means, two stds, one ratio. On distributions: within each class, the model says mk is Gaussian (μ + eδ + ε); pooled across classes mk is a two-bump mixture, not Gaussian — and note the theory only ever needs the 1-D projections to be Gaussian (every accuracy formula acts on the projected scores), which is exactly what the C4 checks test. Full 3584-dim Gaussianity is neither required nor claimed. Finally, σw is axis-dependent by nature: the same residuals give σ = 6 against a gap of 2 along δ̂ (d′ 0.33) and a far cleaner scatter along the whitened axis (d′ 3.4) — the noise never changed; the question asked of it did.

σw is not a property of the frame alone — it is how much the score of a frame of a fixed class jitters from frame to frame, along the chosen axis: the projection of all the irrelevant content (rooms, characters, layout) onto your ruler. Stretching the axis rescales (b − a) and σw together, so only one number can matter:

d′ = (b − a) / σw how many noise-widths apart the two bumps sit, along this axis

d′ is the number because, for Gaussian bumps, it exactly determines the best achievable performance of any decision rule: balanced accuracy = Φ(d′/2), AUC = Φ(d′/√2) (Φ = normal CDF). Anchors: d′=1 → 69%, d′=2 → 84%, d′=3.5 → 96%, d′=0.33 → 57% — barely above a coin flip. The dictionary runs both ways: our per-frame probe scores 0.96, therefore the axis it uses has d′ = 2Φ−1(0.96) ≈ 3.5. No arbitrary "SNR threshold" anywhere — d′ converts to accuracy by an identity.

The terms, in words. Φ is the standard normal CDF — the fraction of a bell curve lying below x (anchors: Φ(0)=0.5, Φ(1)=0.84, Φ(1.75)≈0.96; and Φ(−x)=1−Φ(x)). Balanced accuracy is the average of the two per-class accuracies — a classifier that always guesses the majority class scores 0.5, not high, so it is the honest accuracy for imbalanced data. AUC is the probability that a randomly drawn evidence frame scores above a randomly drawn non-evidence frame — pure ranking quality, no cutoff involved. The two identities are the same geometry at different moments: balanced accuracy asks whether one score clears a fixed midpoint (one noise term → d′/2 inside Φ); AUC compares two scores drawn from opposite classes (two independent noises, variances add → the √2). Both are exact for equal-width Gaussian score distributions — D1 below derives them. Feel the dictionary:

Derivation D1 — why balanced accuracy = Φ(d′/2), step by step

Setup. After projection, the two classes' scores are two same-width Gaussians:

p | N ~ 𝒩(a, σ²),   p | E ~ 𝒩(b, σ²),   b > a,   d′ = (b−a)/σ

The decision rule is a cutoff c: say "evidence" iff p > c. Each class's error is a Gaussian tail area — the probability that noise carries a score across the cutoff:

P(miss | E) = P(p < c | E) = Φ((c−b)/σ),    P(false alarm | N) = P(p > c | N) = 1 − Φ((c−a)/σ) this is the only place probability enters: errors ARE tail areas of the two bell curves

Balanced accuracy averages the two correct-rates:

BA(c) = ½[ 1 − Φ((c−b)/σ) + Φ((c−a)/σ) ]

Best cutoff. Differentiate in c (Φ′ = φ, the bell density) and set to zero:

φ((c−a)/σ) = φ((c−b)/σ)  ⇒  (c−a)² = (c−b)²  ⇒  c* = (a+b)/2 the optimum is where the two densities cross — the midpoint, by symmetry of equal widths

Plug the midpoint back in. At c*, each class's distance to the cutoff is half the gap: (c*−b)/σ = −d′/2 and (c*−a)/σ = +d′/2, so

BA = ½[ 1 − Φ(−d′/2) + Φ(d′/2) ] = Φ(d′/2) both error tails are the same area Φ(−d′/2): the chance noise exceeds half the gap. That symmetry is the whole theorem

In words: with the fair cutoff sitting halfway between the bumps, you err exactly when a frame's noise pushes its score more than half the gap toward the other class — and "gap in units of noise" is d′, so each tail is Φ(−d′/2). AUC follows the same logic one step earlier (no cutoff needed): AUC = P(pE > pN) for an independent pair; their difference is Gaussian with mean b−a and variance 2σ², so AUC = Φ((b−a)/σ√2) = Φ(d′/√2). One more fact worth knowing: for Gaussians of equal width, this midpoint-cutoff linear rule is the exact likelihood-ratio (Bayes-optimal) test — no nonlinear rule can beat it; nonlinearity only helps if the clouds aren't Gaussian, which is what the C4 checks rule out (and measured: per-frame MLP probes ≈ logistic).

3Whitening — why "SNR 0.33" and "probe 0.96" were both true

d′ depends on which axis you read along. The tempting choice is the arrow between the class means, δ̂. It is optimal only if the noise cloud is a perfect sphere — and real noise is elongated: some directions carry lots of irrelevant variance (room identity, other characters). If δ̂ has any component along those, projecting onto it pours that variance into your number. The optimal axis whitens first: it tilts away from the noisy directions, trading a little signal for a lot less noise. Side by side:

Derivation D2 — why the best axis is Σ⁻¹δ (one line of calculus)

Along axis w, the gap is wᵀδ and the noise variance is wᵀΣw, so d′(w)² = (wᵀδ)² / wᵀΣw — a generalized Rayleigh quotient. Substitute u = Σ1/2w: d′² = (uᵀΣ−1/2δ)²/‖u‖², maximized when u is parallel to Σ−1/2δ (Cauchy–Schwarz), i.e. w ∝ Σ−1δ, with maximum d′² = δᵀΣ−1δ. A trained linear probe finds this axis automatically — which is why probe accuracy, not the δ̂-projection, is the honest measure of the code.

The measured resolution of the old paradox: along δ̂ the separation is 0.33 (the old "SNR"); the whitened d′ implied by the 0.96 probe — and confirmed by direct Ledoit–Wolf Mahalanobis measurement — is ≈ 3.4. The per-frame code is strong. Which sharpens the puzzle: if every frame is separable at d′ ≈ 3.4, why does the model fail? Because of what pooling does to that number.

Measured d′ on the steps task, for reference throughout: question-first bench (L19 frame reps) — naive axis 0.21–0.64, whitened 3.2–3.5 across all N-sweep and crowding regimes; deployed locus (room-token carrier messages) — whitened 2.2–2.4 at L14–20, character token 1.1, last token ≈ 0.4; frames-first query-blind frame tokens 0.57. 4What summing does: signal adds like a ruler, noise like a drunk

Pool the frames, S = Σk mk, and read with any axis w. Projection is linear, so the score of the sum is the sum of scores:

wᵀS = N(wᵀμ) + g·(wᵀδ) + Σk wᵀεk constant  +  count × gap  +  accumulated noise

Read it term by term. The first term is the same for every sample — N copies of the shared component, a constant offset a linear readout simply subtracts. The second term is the signal: wᵀδ is the vector arrow δ converted into a scalar step size along your ruler — call it Δ. Every evidence frame pushes the score up by exactly one Δ, so the score's mean is a staircase in the count: base + g·Δ. (Pick an axis with w ⊥ δ and Δ = 0 — that axis is count-blind; pick w = w* and Δ/σw is maximal.) This staircase is exactly why regression probes find R² ≈ 0.85–0.89: the count is linearly present in the mean. The third term is the bad news, and here is precisely why it grows as √N: the εk are independent across frames, and variances of independent quantities add:

Var(Σk wᵀεk) = Σk Var(wᵀεk) = N·σw²  ⇒  std = σw·√N a drunkard's N steps: forward and backward stumbles partially cancel, so distance from start grows like √N, not N

So the signal staircase keeps a fixed step Δ while the fog around each step widens as √N. Divide one by the other:

count-level discriminability   d′N = d′ / √N

At N=8: 3.4/√8 ≈ 1.2. A 96% per-frame decision became a ~73% per-boundary decision — with eight boundaries.

Where softmax actually sins. Attention output is Σk αkvk with Σαk = 1 — a weighted average, i.e. the sum divided by (effectively) N. Two separate verdicts follow. At fixed N, the division is innocent: dividing by a constant shrinks the gap Δ and the noise σw√N by the same factor, so d′N — and therefore the achievable accuracy — is identical for mean and sum. Measured: both decode at 0.44. Anyone blaming "the softmax denominator" for the fixed-length failure is wrong, and we were, for a while. Across varying N, the average is guilty: an average can only encode the fraction g/N, never the count g — two evidence frames out of four produce the same average as four out of eight. Count and length are fused into one number, which is exactly the failure at lengths beyond the training range ("length-OOD"): swapping the mean for an unnormalized sum in a small trained adapter is worth +24pp on unseen counts/lengths; the model's raw answers regress toward a length-dependent middle value; and two causal pokes at inference time point the same way — multiplying attention outputs by a constant > 1 ("GAIN", which breaks Σα = 1) helps at long sequences, while sharpening the softmax ("temperature", which keeps Σα = 1) does nothing. One sentence to keep: the average fails because it is intensive, not because it divides.

The whole softmax story, start to finish

When the counting failures first appeared, softmax was the obvious suspect. Attention divides by its denominator; a count is a magnitude; dividing a magnitude shrinks it. The story almost writes itself — and it was, in fact, this project's original working theory.

The first careful experiment acquitted it. We took the same eight frame vectors from the same samples and decoded the count two ways — from their raw sum, and from their mean (the sum divided by 8: exactly the crime softmax was accused of). If division destroyed the count, the mean should be worse. It wasn't: 0.44 versus 0.44, identical. Dividing by a constant shrinks the count's signal and the noise around it by the same factor, and a ratio doesn't care — a quieter record isn't a damaged record. Whatever breaks counting at a fixed length, it isn't the denominator; it is the √N fog above. The naive charge was dropped — and that acquittal is what gives the rest of this story its credibility.

But softmax does commit a crime — a subtler one, visible only when the length varies. An average can answer "what fraction of the frames had evidence?" but cannot, even in principle, answer "how many" — the count was divided by the very thing that changes. Two evidence frames of four and four of eight produce literally the same averaged vector: not fainter, not noisier — the same point. Remove every drop of noise and the two worlds stay indistinguishable. A collision, not an attenuation.

What to look at: the same two worlds on two rulers. On the count ruler (sum), "2 of 4" and "4 of 8" sit apart; on the fraction ruler (mean), they land on the same point — with zero noise involved. The collision, drawn.

Collisions leave fingerprints, and we found four. (1) Two otherwise-identical adapters, one summing, one averaging, trained short and tested long: they tie at any fixed length (as the acquittal predicts) and split by 24 points across lengths (sum 1.00, mean/softmax 0.76, 3 seeds) — damage precisely and only where collisions become possible. (2) Interrogating the constraint itself: two inference-time pokes that both change magnitudes, of which only one breaks Σα = 1. Breaking it (GAIN) bought +0.20 at length 8; sharpening within it (temperature) bought less than nothing. The scale was never the issue; the constraint was. (3) The model's errors have the shape of a fraction-reader forced to name a count: its answer moves only ~0.2 counts per true count (a faithful counter moves 1.0), and it regresses toward a middle — undershooting high-answer tasks by up to 1.7 while overshooting low-answer ones by 0.8. The sign flip is the tell: attenuation drags everything toward zero; only a pull toward a learned middle pushes from both sides. On rooms the collapse is total — the model answers "3" almost regardless of truth. (4) The alibi-breaker: give the same model chain-of-thought, carrying the tally in text, outside the pooled representation — and the bias vanishes, ≈0 at every length. Same eyes, same frames, same weights. The disease lives in the averaged carrier and nowhere else.

Then we found the accomplice. Softmax is not the only normalizer here — RMSNorm rescales every token before every sublayer, keeping direction and discarding length (§8). Even a count that escapes the softmax as a magnitude has nowhere to live: injecting an artificially amplified count-magnitude into the carrier, we watched normalization first tolerate it, then saturate it, then destroy it (decodability 0.37 → 0.75 → falling at extreme doses — the exact arithmetic of dividing a vector by its own growing norm, predicted before the run; C6). The architecture is intensively normalized end to end; extensive quantities are homeless in it.

Which supplies the ending: if normalization is the villain, un-normalized accumulation should be the hero — and it is. Every readout built on an unnormalized tally extrapolates to lengths and counts it never saw (soft-OR 1.000, sum 0.996, the rooms tally 0.96–0.98 on held-out counts); every learned or normalized readout collapses on the same test, some to zero (C7, Part IV). The moral in one line: normalization never hurt the count by making it small — it hurt by making different counts identical; and the cure is not amplification but an accumulator whose divisor is 1.

5From d′ to exact-count accuracy — where the "thresholds" come from

The count takes values 0…N, so the projected pooled score is drawn from one of N+1 Gaussians, evenly spaced Δ apart, all of width σw√N. Be careful not to confuse these with §2's two clouds — they live one level up: in §2 each dot was one frame and there were two classes; here each dot is one whole sample (all 8 frames pooled), and there is one bump per possible count — the distribution of wᵀS over samples whose true count is g. Their centers are the §4 staircase (base + gΔ); they all share the same width σw√N because every sample, whatever its count, sums exactly N frames' worth of independent noise. The optimal decoder picks the nearest mean — i.e. rounds — and its decision thresholds are not tuned: they are forced to be the midpoints between adjacent count means. An interior count is read exactly iff the accumulated noise stays within ±Δ/2:

P(exact | interior g) = 2Φ(d′/(2√N)) − 1,    P(exact | g = 0 or N) = Φ(d′/(2√N)) boundary counts have one neighbor → one-sided error; overall accuracy = mixture over the count prior

Unpacking that last line slowly, because it feeds every headline number: an interior count (g = 3 of 8, say) can be misread in two directions — noise pushing the score past the upper midpoint or the lower one — hence the two-sided 2Φ(·)−1. The boundary counts g = 0 and g = N have only one neighbor to be confused with, so only one tail can hurt them: their per-count accuracy is the higher one-sided Φ(·). 6Two theorems the data echoes

Nothing placed after the sum can help

For Gaussian classes with shared Σ, the matched-filter score w*ᵀS is a sufficient statistic: the sum's entire information about the count is in that one scalar, so no function of S — an MLP, anything — can beat the linear readout + rounding. The intuition, without the formalism: conditional on the count, S is a Gaussian whose mean moves only along one direction as g changes. Every component of S orthogonal to that (whitened) direction has exactly the same distribution for every g — it is pure count-free noise. A nonlinear readout can only mix those count-free components back in with the matched-filter scalar, which adds noise and never signal. Note what this is and isn't: it is a statement about the statistics of S under the checked model (C4), not an assumption that the network "computes with Gaussians" — and if reality deviated from the model, an MLP could exploit the deviation. Measured: it can't — MLP never beats linear on the aggregate, in all 21 regimes tested (C3) — which doubles as one more adequacy check.

Derivation D4 — the sufficiency argument, honestly sketched

Conditional on g, S ~ 𝒩(Nμ + gδ, NΣ): a Gaussian shift family — only the mean moves with g, along the fixed direction δ. The likelihood ratio between any two counts g₁, g₂ is exp{(g₁−g₂)·δᵀ(NΣ)−1(S − const)} — a monotone function of the single scalar t = δᵀΣ−1S. By the Fisher–Neyman factorization, t is sufficient for g; by sufficiency, the optimal decision based on S equals the optimal decision based on t, which is the matched filter + nearest-mean rule of §5. Any post-pool nonlinearity can at best tie it.

A per-frame gate escapes the √N tax

Threshold each frame first, then count the votes:

ĝ = Σk 𝟙[wᵀmk > c],   perr = 1 − Φ(d′/2)  (per frame — no N in it),   ĝ − g = #FP − #FN  ⇒  P(exact) = P(#FP = #FN) compare: linear pool error is governed by d′/√N → 0; the gate's error is governed by d′ alone, and residual ±1 errors partially cancel

Each decision is made at the full per-frame d′ (error p ≈ 4% at d′ = 3.4) before any noise can accumulate — the continuous noise is destroyed frame-by-frame at the threshold, so there is nothing left to add up as √N. What remains are discrete ±1 mistakes, and a false-yes cancels a false-no: the count is exact whenever the two kinds of error balance, which keeps the gate's curve nearly flat in N (toggle it in the §5 interactive). This is why sharp-gate-then-sum reaches ~1.0 where every post-hoc readout caps, and why DeepSets puts its nonlinearity φ inside the sum.

7Beyond two clouds: K channels and the tally vector

Counting needed one binary predicate per frame. Distinct-rooms asks for the support size of a categorical variable — which room was C in — so the model becomes K clouds, one direction δr per room. Pooling then accumulates a tally vector: room r's channel holds nr·Δr plus the same √N noise. Every task is a function of the tallies (n₁…nK), and the failures split into two grades: linear tasks (steps, co-occupancy read one channel) fail only statistically, via d′/√N; set-function tasks (distinct-count = Σr 𝟙[nr > 0]) are nonlinear in the tallies, so a linear readout cannot express them even noise-free — a structural failure stacked on the statistical one, with once-visited rooms (tally barely above the noise floor) dominating the errors. This predicts rooms' undercounting at high distinct-counts (measured: g5 collapses to 0.18) and retro-dicts the fixes: sum for additive answers, soft-OR (per-channel threshold, then sum) for support-size answers — exactly the two readouts that worked.

8Why magnitude codes die at every norm

One more piece of architecture completes the picture. Before every attention and MLP sublayer, the transformer normalizes the token it is about to read:

RMSNorm:   h  →  √d · h/‖h‖ ⊙ γ the length of h is thrown away; only its direction (times a fixed learned per-dim scale γ) survives

Now recall where the count lives after pooling: S = Nμ + g·δ + noise — the count is a magnitude, "how far along δ the pool has traveled." Normalization keeps direction and discards length, so a magnitude code must smuggle itself into the angle of the token — and both extremes lose:

Normal regime (‖μ‖ ≫ g‖δ‖ — the real model, ratio ~100:1): the direction of S is dominated by μ; the count tilts it by an angle of order g‖δ‖/(N‖μ‖) ≈ a fraction of a percent. After normalization, that tiny tilt is all that remains of the count — the 1% number from §1 is not just small, it is the entire surviving signal for everything computed post-norm.

Dosed regime (g‖δ‖ ≫ ‖μ‖ — our amplification experiments, C6): the direction of S converges to δ̂ for every g ≥ 1 — a count of 2 and a count of 8 normalize to nearly the same unit vector. The g-dependence collapses; attention keys, values, and MLP inputs all go count-blind exactly when the magnitude code dominates. That is why the dose ladder rises, plateaus, then declines: the rise–plateau–decline is (h + λgδ)/‖h + λgδ‖ arithmetic, observed.

Pair this with softmax (a convex combination, Σα = 1 — intensive, §4's note) and the conclusion is architectural: the network is intensively normalized end to end; extensive quantities like a count have nowhere native to live. That is the deepest root of the whole story, and why the working fixes all read the tally outside the normalized stream.

1 · What exactly is a "message" — and why it is the model's own computation, not a proxy. In attention at layer L, the information moved from frame f's tokens into a carrier position c is

We capture q/k/v projections and the rotary embeddings during a normal SDPA forward and recompute the carrier row offline — no eager attention, no model modification. One 3584-dim vector per frame, per carrier token, per layer. The step that makes this rigorous: once A is fixed, the attention output is linear in the A[c,j]·vj terms, so grouping by source frame is an exact partition:

Could the information flow some other way? Three lines of defense, in increasing strength. Measurement: the d′ map covers every question token, the last token, and block combinations — alternate carrier locations are enumerated, not assumed away. Causal necessity ("E5" = our intervention suite of doses and scrubs — this is what actually closes the hole): the scrub removes one declared token's δ channel at every layer of a window; if the answer reached the output by any route not transiting that channel, behavior would survive — instead it collapses, while random directions/ subspaces, neutral tokens, other information-bearing tokens (char1), and late windows all leave behavior untouched. The dose adds the converse (only the causal carrier's dose moves behavior), and the mid-vs-late scrub timing matches the independently measured restoration staircase. Prediction: if the operative aggregation lived elsewhere, the accuracy ceiling computed from these messages would have no reason to predict measured decodes across twenty regimes with zero fitted parameters. Honest limit: scrubs prove necessity of the declared direction(s) at the carrier, not a full path decomposition — redundant-but-unused routes demonstrably exist (decodable ≠ used); attention-edge path-patching is the gold-standard upgrade, named as future work.

2 · Which token is the carrier. We do not guess: a per-token × per-layer d′ map over all question tokens finds where the per-frame evidence is most separable. C2"Superposition" is measurable noise correlation

Rules out: treating single-pass interference and the SNR story as two separate phenomena.

The √N step assumes per-frame noises are independent. Measured: in every joint-pass cache the cross-frame residual correlation is ρ ≈ +0.09–0.13; in the matched multipass (isolated-frame) caches, ρ ≈ +0.004–0.014. Same frames, same task — the only difference is whether the model saw them in one forward pass. Single-pass processing is what correlates the noise; isolation removes it. This is the quantitative form of the "superposition" observations, and it has a name in the population-coding literature: information-limiting correlations (Moreno-Bote et al. 2014). Nuance: the ρ-penalized prediction replaces the accumulated noise σ√N with σ·√(N(1 + (N−1)ρ)) — correlated noise does not average away. Measured accuracies track the iid prediction better than that penalized version — a full-dimensional readout can project out the shared-direction part of correlated noise, so only the component along the matched filter is irreducible.

What to look at: joint vs isolated bars per task — an order of magnitude apart. Fig. 5 — cross-frame noise correlation ρ (steps: .085 → .014; co-occ: .096 → .004; matched cache pairs, same samples).

The readout problem in sixty seconds — and why the obvious fix fails

The picture. After all the pooling, the count that survives is written on the last-token state along some direction u — think of it as a message scribbled at one particular angle on a crowded page. The announcer (the unembedding matrix WU) reads that page through fixed glasses: each digit token has one frozen reading direction, learned during pretraining for predicting digits in text. Nobody ever forced the writer and the reader to agree on an angle for "analog tally accumulated at a room token" — that situation was too rare in pretraining to matter. So the message and the glasses ended up nearly perpendicular.

The three lines. The emitted score for digit k is a dot product with a frozen row:

logit(k) = wk · x,    x = (count)·u + everything else

so what reaches the answer is only the overlap between the reading rows and the count's direction:

usable separability ≈ d′available × (overlap of reader with u)     measured: cos ≈ 0.005–0.056
d′ 2.47 available on the page  →  d′ 0.51 through the glasses  →  accuracy ~0.2 (the law, applied to 0.51)

Same page, same ink — the reader keeps a fifth of the separability, and the same law that predicts everything else predicts the model's actual score from that residue. Causal proof it's the reader and not the page: inject the count at strength λ=64 and a correctly-angled probe reads the final state at 0.783 while the model emits 0.133. And the angle is a constant of the frozen weights: the native reading direction barely moves across sequence lengths (cos 0.82–0.92 between N=2/4/8), so the wall neither grows nor shrinks with N — it's just always there.

Why the obvious fix fails (Garcia's trap). "Just re-grind the glasses": replace the digit rows of WU with the correctly-aligned direction. We did (deploy_readout_fix, after Garcia 2026, arXiv:2605.03258). Under constrained scoring it works — but in free generation it collapses (Garcia: to 0%), because those same rows are consulted at every token of every generation, not just the final answer: regrinding the glasses for one message breaks the announcer's ability to read everything else on the page. A frozen reader is load-bearing.

The intuitive fix, in one sentence. Don't teach the reader a new angle — either write the message at the angle the reader already watches, or hand the answer over without the glasses. Concretely, the two working routes: (a) realign the writing upstream — small LoRA on the routing (Q/V) rotates the count into the direction the frozen reader expects (Garcia: 83%); or (b) bypass the reader entirely — keep the tally outside and read it directly with an aligned probe, then say the number symbolically (our tally register's readout, and the reason the λ-dose "repaired" column works at 0.783). Both respect the same principle: the frozen readout is part of the model's language machinery — route around it, never rewrite it.

And the sharpest confirmation — the sufficiency sign-flip. For counting, an MLP on the pooled state never beats linear (21/21 regimes — C3), because counting is linear in the tallies. Part IV — What would fix it

10Requirements for any cure, and the honest scorecard

RequirementWhy (from the theory)
R1A per-element nonlinearity before poolingdecisions must be made at per-frame d′, before noise accumulates (§6); post-pool functions are futile (sufficiency, C3)
R2An extensive (unnormalized) reductionconvex combinations are intensive — they encode fractions, confounding count with length across N (§8)
R3A direct readout of the reductionthe frozen head is misaligned (cos ≤ 0.01) and ignores even a ×64-amplified, 0.78-decodable signal (C6)

Retrain the backbone (LoRA)? Works by raising per-frame d′ (measured 0.4 → 2.3–2.7 — δ̂-axis numbers from the June decomposition, comparable within the row but not to the whitened 3.4; accuracy follows) — causal proof that d′ is the lever, but per-task, model-specific, and R3 stays unsolved (0.99 IID / 0.035 count-OOD: the head caps). Serial decomposition (CoT / per-frame passes)? Task- and model-agnostic, satisfies R1 by making N=1 everywhere; costs N× compute; the zero-training baseline any fix must beat (oracle-CoT → 0.94–1.0). An adapter on the frozen model — read → query-conditioned gate → fixed extensive reduction (sum / soft-OR) → direct read? The only shape hitting R1+R2+R3 at once while staying frozen and task-family-agnostic; instantiated twice already (isolation-mask + Σσ: 0.95–1.0 with count extrapolation; frame-axis DeepSets adapter). The honest open costs: per-frame supervision (or a self-supervised look-again signal) for the gate, and the per-frame extraction ceiling under crowding becomes the new binding constraint.

What the theory says cannot work, so stop spending on it: any smarter readout placed after the existing pooled state (C3); attention re-weighting that keeps Σα = 1 (still intensive — measured: temperature null, GAIN>1 modest); better aggregators over frozen low-d′ inputs (mamba over frozen reps: capped, as measured); and pumping more signal into the carrier without touching the readout (C6 — the 5.9× gap).

The clean solution, designed from the diagnosis alone: a query-conditioned tally register

If one knew only the theory and none of the project's prior methods, the requirements force a single architecture — five components, each answering one measured failure:

componentwhat it doeswhich finding forces it
1 · Locateper-token × layer d′ map (~400 samples) finds the carrier — empirically the last query-completing entity token — then a 15-min scrub verifies it causallycarriers are task-dependent; the model consumes a single binding site (C7 anatomy)
2 · Decideper-frame, per-channel gate σ(wc·mk) on the carrier messages, trained by look-again distillation — the frozen model labels single frames at 0.96–0.99, teaching its own gate; no human labelsdecisions must happen at full per-frame d′, before √N accumulation (§6) — and only where d′ suffices (measured on two sibling 9-channel tasks: at per-channel d′ ≈ 1.1–1.5 hard thresholds collapse and soft pooling wins — the gate has a crossover)
3 · Accumulatean integer-ish tally vector n̂ = Σk gates, held in a side register outside the residual stream — never divided, never normalizedsoftmax is intensive (§4) and RMSNorm kills magnitude codes (§8): extensive quantities cannot live in the normalized stream
4 · Reducea tiny fixed algebra chosen by the question type: Σ (count) · Σ𝟙[n>0] (support size) · position-ops (temporal — the position channel exists at the carrier, 0.99 decodable)near-zero learned parameters here is what buys count/length extrapolation — nothing to memorize a training range into

The honest coda: components 2–4 reconstruct the DeepSets/Σσ shape the project's empirical search had already converged on — which is the point, not an anticlimax: the theory leaves no other shape available. What the from-scratch design adds: self-supervised gate labels, the out-of-stream register, the symbolic re-entry readout, and the d′-sufficiency condition on when to gate at all. The deepest version is architectural: transformers lack an extensive register as a primitive; everything above is a prosthesis for that missing part.
