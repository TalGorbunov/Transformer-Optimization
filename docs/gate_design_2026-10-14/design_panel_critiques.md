# DESIGN native-trainingfree: NAV gate: Null-Anchored Verdict gate (the frozen model's own per-block yes/no, in the fenced scan, calibrated by a foreign-null anchor and the question's own peak; zero trained parameters)

Keep the pipeline exactly as it is (batched fenced scan with the question in the shared prefix -> keep decision -> frozen packed two-pass re-read) and replace the trained L20 logistic probe by a readout the backbone already produces: the first-answer-token log-odds s_i = logsumexp(yes spellings) - logsumexp(no spellings) of the per-block judge line "Does this frame contain evidence needed to answer the question above? Answer yes or no." appended after frame i inside its fenced block. This readout exists in code (`core/fastpath.py::fenced_forward(judge_ids=..., judge_vocab=...)`, parity-tested 2026-09-30) and on the record it RANKS needles almost perfectly (unfenced D regime on VNBench, 9,034 units: per-task AUC 0.91-1.00, pooled 0.937; `outputs/scaleup/vnbench/qwen2.5-vl-7b/s1u_unit/D_frame_lo/20261010_225007_D-frame_reslo/report.txt`); what failed in the record is calibration (literal "yes" keeps 13% of needles; one global threshold gives recall 0.49 at spec 0.99). The design fixes calibration with two in-model anchors computed in the same scan: (1) a NULL anchor s_null = median verdict over three fixed foreign natural frames (frames from a video outside every benchmark) appended as three extra blocks per question, which estimates the question's own haystack baseline without labels (the dummy-document / content-free-input precedent: Found in the Middle 2406.16008, ICR 2410.02642, Calibrate Before Use 2102.09690, OccamToken 2605.29657, ReQuest 2607.01737); (2) a PEAK anchor s_max = the best frame of the question. The midpoint rule keeps frame i iff its verdict is closer to the peak than to the null, i.e. s_i - s_null >= (s_max - s_null)/2, and declares k = 0 when no frame beats the null by m0 = 2 log-odds. Every quantity is block-local (prefix + one frame + 27 judge tokens, identical token set at every N), so the threshold cannot dilute with N; the only N-dependence is the sqrt(2 ln N) extreme-value drift of a weak peak, which is measured, not assumed. The count k is emergent (no budget, no top-k, no NMS: duplicates are kept for the reader to count), the re-read sees an exactly-zero residual, and the same scan still captures the L20 slot states, so the timestamp-supervised probe (0.989/frame) and the label-free NAV gate are compared on identical frames at no extra GPU cost: the label-source ablation the peers asked for.

CALIBRATION: Midpoint-between-anchors on block-local log-odds. Per question: s_null = median verdict of 3 fixed foreign-null blocks; g_i = s_i - s_null; g_max = max_i g_i. Declare k = 0 iff g_max < m0 (= 2 log-odds: no frame makes 'yes' 7.4x more likely than a content-bearing irrelevant frame does). Otherwise keep i iff g_i >= g_max/2 ('closer to the peak than to the null'). How many to keep is never decided: each frame is judged against two per-question constants, so k emerges, duplicates stay, k = N is allowed, and no quantity k/N, top-k, top-p or Otsu class proportion enters the rule. N-invariance: (i) every s_i and s_null comes from a forward over prefix + ONE frame + 27 judge tokens, the same token set at N = 8 and N = 256, so there is no shared softmax across frames to dilute (the 1/N dilution of negative result (c) is a property of the joint forward only; SSMax 2501.19399 and the record's share law k e^s/(k e^s + N - k) state why post-softmax mass cannot carry a fixed threshold, and a fenced block has no such denominator); (ii) the null anchor is a per-question constant; (iii) the peak anchor equals the strongest needle whenever the needle gain exceeds the haystack extreme, which is N-free; when needles are weak the haystack maximum grows like sigma_h * sqrt(2 ln N) (about +1.3 sigma_h from N = 8 to 256), the one logarithmic N-dependence, which the first experiment measures as kept-count vs N on identical questions. Contrast with the record's rule 'within 2 log-odds of the best' (recall 0.95 / rejection 0.90 on ~2 stored negatives per positive, exact set 0.78): that rule has only the peak anchor, so it cannot represent k = 0 and its window is an absolute 2 regardless of how far the question's haystack sits below the peak; the null anchor supplies the missing scale.
CROSS-FRAME: By over-keeping plus the joint re-read, never by the gate reasoning across blocks. The judge line asks whether the frame holds evidence NEEDED for the question (not whether it answers it), and the question with all its referents sits in the prefix, so for anchor-relative questions ('what happens after the red car appears') the verdict fires on frames showing either referent; the packed re-read sees the kept frames in time order and resolves after/before/first/last (the two-pass read already does ordering at 0.744 circular vs plain 0.518). For 'how many distinct objects' with duplicates: no NMS and no run-merge in the gate, every appearance is kept, de-duplication is the reader's job (its ceiling, counting inside images 0.21, is a reader wall, not a gate wall). For 'which did NOT happen': the options are in the prefix, the verdict fires per depicted option, the reader eliminates. For MMReD every-frame qtypes (where_spend, rooms_visited): all gains sit near g_max, the midpoint keeps everything, the gate is a no-op and the read is the plain read, which is the correct behaviour where relevance is not sparse (Lens 4: that is the k-wall, not a gating problem). Structural blind spot, stated in the paper: relevance that exists only through another frame's appearance (anchor-via-appearance); Lens 4 finds no such task in VNBench, HERBench-lite or MMReD, and the HERBench AG* rows are text-answerable. The label-free extension if it is ever needed is a second scan whose prefix is question + round-1 kept frames (Beam Retrieval / MDR template, 2N blocks), judged by the same NAV rule; not proposed within the four weeks.
FIRST EXPERIMENT: what: Paired label-free-vs-supervised gate on identical frames. One capture per N of the held-out fold-B VNBench rows (the fold the probe was NOT fitted on), fenced_qfirst, batched, with `--judge` (stage-2b wording) and 3 foreign-null blocks appended, storing X (L12/20/24 slot states) and J (judge logits). CPU afterwards: (1) in-fence verdict AUC per task against the N-k haystack frames (not the stored ~2 negatives); (2) NAV midpoint rule: per-frame recall / rejection / exact-set rate / kept count, by task and by k, at every N; (3) the fitted gate `s2_gate/fits/gate_L20_fitA.npz` applied to the same X (the record's 0.989 row, paired); (4) null diagnostics: |s_null - median_i s_i| at N=128, s_null across the three null frames; (5) sensitivity over rho and m0 from the stored J (no new GPU). Then re-run only the read (`eval.csv` keeps `kept`) behind NAV vs behind the probe at the same N. | gpu_h: ~4 GPU-h for the three VNBench captures (5.7K + 20K + 39K blocks at ~1 GPU-h per 20K blocks, x1.15 for the judge) + ~0.5 GPU-h MMReD + ~1 GPU-h for the 1,800 reads; one A100-40GB (a100-public) or rtx6k-shared (--exclude=n317), --time 6h each; CPU analysis in minutes. | band: In-fence verdict AUC >= 0.95 pooled against the haystack at every N; NAV per-frame accuracy 0.97-0.99 at N=16/64/128 (probe 0.989 on the same frames) with recall >= 0.95 and rejection >= 0.98 on ret_*, cnt_*, ord_edit1 / ord_insert1; exact-set rate >= 0.75 at N=128 (probe 0.90); kept count on identical questions within 1.3x from N=16 to N=128; k = 0 declared on >= 90% of MMReD answer-0 rows with <= 5% false k = 0 on VNBench; two-pass accuracy behind NAV within 3 points of behind the probe at N=128 (0.866-0.880). | kill: Pooled in-fence AUC < 0.93 at N=128 (ranking itself is lost in the question-first layout), OR NAV rejection < 0.96 at N=128 on the tasks where AUC >= 0.98 (i.e. >= 5 leaked haystack frames per question even where ranking is near-perfect: calibration cannot be fixed by anchors), OR the two-pass accuracy behind NAV at N=128 falls below the plain read (0.69). # DESIGN relational-set-gate: Residual Set Gate (RSG): a 2M-parameter relational gate over the fenced scan's per-block states, residual on the 0.989 probe, with non-softmax message passing over hard candidates

Keep the pipeline exactly as it is (fenced scan -> gate -> frozen packed two-pass re-read) and replace only the keep decision. Instead of thresholding each block's layer-20 <|vision_end|> state alone, the N slot states plus the prefix's question-end state at the same layer are handed, after the whole scan, to a small ordered-set module that outputs keep/drop per block. The module is RESIDUAL on the existing logistic probe: keep_t = 1[p_t + Delta_t > 0], where p_t is the frozen probe logit (the record's 0.989/frame gate) and Delta_t comes from two layers of sigmoid-gated, unnormalised message passing over the candidate set C = {t : p_t > tau_low}, with a relative-time bias in seconds, a question token and a learned null token. At initialisation Delta = 0, so the gate IS the current gate and every change is measurable against the record; non-candidates contribute exactly zero (the record's own SOFTGATE lesson: only an exactly-zero residual is N-invariant), and the aggregation has no softmax row normalisation, so the messages do not obey the share law that dilutes attention mass as 1/N. It is trained offline by BCE on labels by construction (VNBench needle_time intervals, already captured at N=16/64, plus synthetic composites spliced into the existing frame pools: duplicates vs distinct, right-after-X, k=0 displaced questions, foreign distractors labelled 0), never by the answer loss, with the reader frozen. What it buys on the record: (i) under the official uniform grid the per-frame gate keeps needle RUNS (14.5 / 28.9 blocks for 2.9 needles at N=128/256) and counting pays (cnt_edit1 0.84 vs 0.98 with one frame per needle; k=5-6 0.63 vs 0.79); a content-aware run representative fixes this without swallowing back-to-back needles 1 s apart, which a naive adjacency merge does; (ii) the probe's false positives (0.16 -> 0.81 per question from N=16 to 128 planted, exact set 0.94 -> 0.90) are decided with the within-question context the record shows nearly works label-free (within 2 log-odds of the best: 95% kept / 90% rejected); (iii) the relational classes the peers named (duplicates vs distinct, anchor-relative, absence) become representable, and the gate's precision/recall is reported per frame as a function of N, which no paper in the digest does. Cost is zero extra frame forwards; the gate is about 10^-6 of the scan's FLOPs and under the uniform grid the re-read shrinks from about 5,400 to about 900 tokens at N=256.

CALIBRATION: How many to keep is never a budget, a top-k or a top-p: it is the sign of a per-block logit, keep_t = 1[p_t + Delta_t > 0], trained by BCE on construction labels, the same rule as the deployed probe and as Sparse RAG's fixed sigma on P(yes); k is whatever the signs say, 0 included. N-invariance holds by construction at every stage, not by fitting at one N: (i) p_t is computed from a fenced block that sees the prefix and itself only, so the share law k e^s/(k e^s + N - k) (e^s = 1.94 at L20, the quantity that refuted thresholding attention mass) does not apply; the record shows the probe's accuracy identical at N = 16 and 64 and its miss rate 0.01 flat to N = 128. (ii) Delta_t is a sum of sigmoid-gated messages, not a softmax row: no normalisation across blocks, so a needle's message to another needle is the same whether 10 or 250 fillers exist; fillers outside C contribute exactly zero rather than a diluting residual, the SOFTGATE lesson applied inside the gate. (iii) No absolute index, no N feature: time enters only as signed differences in seconds through bucketed biases, so the function is defined identically at any N and any fps. (iv) The only N-dependent quantity is |C|, the probe's false positives (about 1 per cent of N) plus runs; the training set spans N = 16, 64 and 128 and |C| per question is reported at every N up to 256 with the gate's per-frame precision/recall, so drift, if any, is measured rather than assumed. (v) Within-question relative information, which the record shows nearly suffices label-free (within 2 log-odds of the best: 95 per cent kept / 90 per cent rejected, exact set 78 per cent; top-k with the true k 94 per cent), is available to the module through the messages, but it is anchored by the absolute labelled threshold of p_t, so k = 0 and k = N do not break it as the relative rule alone does. Zero-init of Delta guarantees the deployed calibration cannot start worse than the record's.
CROSS-FRAME: Each candidate's decision Delta_t is a function of the other candidates through two rounds of signed-time-aware messages, so the four classes the peers named are representable, and each has a label by construction and a measurable cell. (1) Needle runs under the official grid (the binding case on the record): at 6.4 fps a 1 s needle covers 6-7 sampled frames and the per-frame gate keeps all of them (28.9 blocks for 2.9 needles at N = 256, exact set 0.51); the module sees same-second neighbours through the 0..1 s bias bucket and their near-identical states, and keeps the representative only; because it compares content, two different needles 1 s apart (back-to-back inserts, which a naive adjacency merge swallows) stay two. (2) Duplicates vs distinct: for 'how many times does X appear' all occurrences are kept (the reader counts them); for 'how many distinct objects' one per identity is kept, a decision that needs the other candidates' states (cosine of slot states is the EFS/Vgent precedent, learned here) and the question token to know which of the two the question asks; the frozen reader then counts d packed distinct frames, the regime it handles, instead of de-duplicating k views (the record: duplicate views inflate its count, clip5 E 0.807 vs frame 0.880). (3) Anchor-relative ('what appears right after X'): the target candidate attends to anchor candidates through the signed time bias (after = negative dt bucket) and the question token names X; anchor + target are kept, the other needles dropped, so the read gets 2 frames instead of 4; on VNBench proper this never binds (the per-frame gate keeps all 4 and the reader orders at 0.98/0.94/0.88), so it is a constructed cell, reported as such. (4) Absence and negation: 'which did NOT appear' is handled by keeping the frames of the options that did appear (per-frame suffices; the set context calibrates when 3 of 4 appear); k = 0 is handled by the null token plus T5 items (all candidates pushed negative), evaluated on synthetic and HERBench FAM/FOM only, since VNBench has no k = 0 question and no 'not shown' option. # DESIGN reader-signal-distilled: ROUNDTRIP: the frozen reader writes the gate's labels (in-scan verdict rank, cardinality from the gold answer, round-trip verified by the two-pass read)

Keep the gate exactly as it is (a logistic probe on the fenced layer-20 <|vision_end|> state, hard 0.5 threshold, the same keep callable) and change only where its labels come from: instead of the benchmark's needle timestamps, the frozen Qwen2.5-VL-7B labels its own evidence on the label half of the training videos at N <= 16. Three steps per training question, all inside the pipeline that already exists. (1) RANK: in the same batched fenced scan that produces the L20 states, a fixed judge suffix after each block ("Does this frame contain evidence needed to answer the question above? Answer yes or no." — gate_capture.py --judge already stores it, parity-tested) gives a per-block log-odds j_i = logP(yes) − logP(no); it is computed from a prefix + ONE frame forward, so it cannot dilute with N (the record's share-law failure (c) is a property of the joint forward). (2) COUNT: binarize within the question by top-k with k read off the gold answer (ret: 1; ord: the number of listed items; cnt_insert1 / cnt_edit1: the gold count, including 0 on MMReD) — the DPR answer-containment / SeViLA / M-LLM-selector move, and the record's own measured ceiling (top-k with the true k is set-exact on 0.94 of questions). (3) ROUND-TRIP: the top-k set is read with the frozen two-pass packed read; for retrieval and ordering the question enters the label set only if that read reproduces the gold answer (Promptagator's round-trip filter, K=1); counting questions are kept regardless because the reader's miscount, not the set, is the usual cause of failure (two-pass with the exact set: cnt_edit1 1.000, cnt_insert1 0.893 at N=16 on the record). The probe is then fit with BCE on these labels exactly as today; at test time nothing changes: N frame forwards, keep iff sigmoid > 0.5, packed re-read of the kept frames, the paper's prompt byte for byte. The gold answer enters at training only (through k and the round-trip); no timestamps, no stronger LLM, no per-frame human labels; at test the gold never enters. cnt_edit2 (answer = a sum over 4 edited images, k unreadable) is excluded from the label set and reported as a held-out task, as it already is the one wall of the frozen read (0.21).

CALIBRATION: At test time "how many to keep" is never decided: each block is kept iff sigmoid(w·h_L20 + b) > 0.5, and the count is whatever that sum is (k=0 allowed). The absolute boundary is LEARNED by the probe from binary labels pooled over questions, never fit as a scalar on a score distribution. Where cardinality enters is label time only, and there it is read off the gold answer (top-k with the true k, the record's 0.94 set-exact ceiling) at N=16 — no threshold on the judge is ever used, which is exactly the rule the record showed cannot be thresholded (literal "yes" keeps 13% of needles; the model's verdict ranks at AUC 0.92-1.00 but has no absolute cut). N-invariance holds for three structural reasons, none of them empirical: (1) the feature h_L20 and the judge logit come from a forward over prefix + one frame, so N does not appear in either computation (the 1/N share law lives in the joint forward only); (2) labels are per (question, frame) and the only within-question operation (ranking) is done at a fixed N=16 where the frozen reader is reliable, so no scalar is ever fit against N; (3) the probe's threshold is on a per-block posterior, so the expected number of leaked haystack frames is f_FP x (N - k) with f_FP a constant — the same compounding law the timestamp gate shows on the record (false blocks 0.1 -> 1.0 per question from N=16 to 128, missed 0.01 flat, per-frame 0.989 identical at N=16 and 64). The paper reports this as the leak curve (false blocks per question vs N, and two-pass accuracy of rows with 0 / 1 / 2+ false frames: 0.89 / 0.69-0.75 on the record) rather than per-frame accuracy alone. The round-trip filter is applied only at label time and only to ret/ord questions, so it never presumes a keep-rate (TARG) or a cumulative mass (AttnComp top-p), the two label-free "thresholds" the digest shows drift with N.
CROSS-FRAME: The gate stays per-frame; what ROUNDTRIP changes is only the labels, so cross-frame relevance is handled exactly as the current gate handles it, now with a stated boundary (digest lens 4): (i) anchor-relative questions ("what appears after the landmark") are question-conditioned at the block, so the judge fires on every frame where either predicate is visible (both anchor and target get label 1 via top-k with k = 2); the reader resolves first/last in the packed re-read, which is order-aware (packed two-pass 0.88 flat vs the fenced read's 0.48). (ii) Duplicates / "how many times": VNBench counting needles are repeats by construction; k = the gold count keeps every copy, and because the label is top-k on a per-block verdict (not leave-one-out), the verified LOO failure on duplicates (first copy over-credited; LOO the lowest-performing attribution, 2507.04480) is avoided by design. (iii) "Distinct" counts: k = the number of distinct items keeps the best-scoring copy per item, which is sufficient for the read. (iv) Negation / "which did NOT happen": all options are in the prefix, the judge fires per true option, the reader eliminates. (v) Set-valued "every frame is evidence" MMReD qtypes (where_spend, rooms_visited): k = all, the gate is a no-op by label, and the residual is the aggregation k-wall, not a gating problem. Structurally uncovered: relevance that exists only because of another frame's CONTENT (anchored-by-appearance); no task in VNBench/MMReD/HERBench-lite binds there (lens 4's per-task table), so no set-level module is built in this window; if a reviewer insists, the cheapest extension is a 2-layer d=256 encoder over the N ordered L20 states trained on the same pseudo-labels (QD-DETR/VideoITG-C pattern), which keeps the per-frame threshold and adds no forwards. # DESIGN two-round-anchor: ANCHOR2: two-round fenced gating, round 2 = a second fenced scan whose shared prefix holds the question AND round-1's kept frames (with timestamps), scored by a second logistic probe on the layer-20 block state

Round 1 is the measured pipeline, untouched: fenced scan (prefix = question), logistic gate g1 on the L20 vision_end slot state (held out by haystack 0.9951/frame, AUC 0.9993; N16-to-64 transfer 0.9992), kept set K1. Round 2 fires iff the merged anchor count A = |merge_kept_runs(K1)| is in 1..8: a second batched fenced scan of ALL N frames whose shared prefix is [question] ['Reference frames:'] [<time> anchor_1] ... [<time> anchor_A] (anchors at their natural prefix positions; the prefix KV is computed once and expanded over the chunk batch exactly as the question prefix is today) and whose blocks are [<time caption> frame_t] under the per-block position reset; a NEW logistic probe g2 on the round-2 L20 slot state decides keep/drop per block at threshold 0; the final set K = K2 is read by the unchanged frozen packed two-pass re-read in the official layout, and the model generates the answer. Round 2 makes relevance-given-the-anchors decidable per block, because the frozen model's own attention from the block to the anchors' KV does the conditioning (no relational module): 'the item right after X' becomes (same class AND t > t_X), 'the item the clue names' becomes (matches the content of the clue frame now in the prefix). Training is BCE on per-frame labels by construction (anchored questions written over the existing 450 VNBench ord_* videos, whose needle times and item names are in meta), fit on CPU in seconds; nothing is trained inside the backbone, no gradient ever crosses a gate, the reader is frozen. Cost 2N block forwards plus one short prefix forward, about 2x the current scan tokens, still O(N) and N-free per block. Exactly two rounds; no fixed-point iteration.

CALIBRATION: 'How many to keep' is never decided: each block is kept iff g2's logit on its own L20 slot state exceeds 0, a per-frame decision with no top-k, no budget, no cumulative mass and no per-question quantile. It is N-invariant by construction because the round-2 block is scored inside a forward of [prefix_2 ; caption ; frame] whose length depends on A (1..8 anchors, bounded by the trigger) and never on N: there is no softmax over the N frames anywhere in the decision, so the share law k e^s / (k e^s + N - k) (e^s = 1.94 at L20 on the plain read) cannot dilute it; this is the same property that made g1's threshold fitted at N=16 hold at N=64 (0.9992) and the two-pass read flat 0.88 from N=8 to 128. Cross-question calibration across A (the prefix length varies 1..8) is handled by fitting g2 on rows spanning A = 1..8 with per-fit z-scoring, and k=0 target sets (anchor last/first, 'None' answers) are in the training mix so the probe has a correct 'keep only the anchor' mode. The kept count follows from the labels: for 'right after' it is 1 + (needles after the anchor), 1..4 on VNBench; the reader resolves the rest. The only code-side rule besides the two thresholds is the trigger 1 <= A <= 8 (merged 1 s runs), which bounds the prefix and sends every-frame questions straight to the read.
CROSS-FRAME: Taxonomy (lens 4) and what ANCHOR2 does with each. (1) Anchor-relative time ('right after / before X', VISTA Two-Needle, Ego4D NLQ before/after): round 1 keeps every frame of the named class (all 4 needles: the pointwise optimum); round 2 puts the anchor with its time in the prefix and a time caption on every block, so g2 can read (class AND t > t_anchor) per block; K2 = anchor + later needles (<= 4 frames); 'nearest' is left to the packed read, which orders <= 4 kept inserted images at 0.97-0.99 (two-pass ord_insert1/2, every N). (2) Target identifiable only through an anchor's content (VideoChat-Flash clue chains, MDR hop 2): round 1 fires on the clue frame (pointwise visible) but is blind to the target; round 2 exposes the clue's content to every block through the prefix, so g2 scores 'matches what the clue names' per block. This is the one class a per-frame gate cannot represent at any threshold and the class where the multi-hop NIAH gap lives (99.1 single-hop vs 31.3/25.4 multi-hop, VideoChat-Flash). (3) Absence / 'which did NOT happen' (HERBench FAM/FOM): all options are in the prefix already; round 1 fires per true option and the reader eliminates; round 2 adds nothing and is expected to reproduce K1 (part of the no-harm check). (4) Duplicates / 'how many distinct': NOT a round-2 job. Round 1 keeps every copy; de-duplication is a read-format question (enumeration with frame identifiers, lens 6) and g2 is trained to keep duplicates (label 1), never to drop them (DART/NMS-style pruning deletes what counting must count). (5) Every-frame aggregation (where_spend, rooms_visited, MPDR, RLPC 'All'): no selector helps; the trigger (A > 8) skips round 2 and reads K1; this is the k-wall, reported as such. Mechanism: no new relational module; the conditioning is the frozen model's own cross-attention from the block to the anchors' cached KV, the same mechanism that makes question-conditioning work (QGATE: question-blind blocks are chance, question-in-prefix blocks are 0.99). Exactly two rounds: our constructions and the clue chains are one hop; VideoAgent's rounds give 53.8 / 58.6 / 60.2 / 59.8 (saturation at 3, -0.4 at 4); Beam Retrieval needs a score threshold tau to stop a variable chain and MDR fixes n=2; a third round would re-use g2 with K2 as anchors and is left out of this design.

# DESIGN minimal-cvpr: PLANT-GATE: the same L20 logistic gate, trained only on needles planted by construction into disjoint (MINERVA) footage, deployed on VNBench / HERBench with the frozen packed two-pass read

Keep every measured piece of the method (fenced question-first scan on the batched path, logistic probe on each block's layer-20 <|vision_end|> state, hard per-block threshold, frozen packed two-pass re-read with the needle-second merge rule) and change exactly one thing: where the gate's labels come from. The deployable gate is fitted on ~2,000 questions whose needles are planted by our own generator into MINERVA footage (194 videos, 80 s to 100 min, already on /rg, never a method benchmark), with labels that exist by construction and a VNBench-format 4-option prompt in the prefix: subtitle overlays, inserted natural stills/1-s clips cut from other MINERVA videos, duplicates (r<=4), k=0 absence questions, anchored "right after X" composites, and, mandatorily, m>=k planted distractor needles with no question plus cross-question negatives so that "foreign frame" carries no label (Visual Haystacks / V-NIAH-D rule). The gate is then scored, with no refit, against VNBench's benchmark timestamps (existing captures, zero GPU), HERBench TSO/SVA human intervals, and the official VNBench circular score, so the paper's leave-every-benchmark-out claim is per-frame accuracy flat in N (16 to 256) on labels the gate never saw. The record already says why the naive version of this fails and what the generator must contain: the HERBench-label gate transfers to VNBench at L20 AUC 0.82 / acc 0.79 (edit needles AUC 1.00, inserted pictures 0.66-0.83, bias off by 20 points of specificity even at AUC 1.0) and the MMReD gate at AUC 0.59 (jobs 181600/181601, 2026-10-14), so the synthetic set must match the target's structure (needle-in-real-footage, MCQ prefix, max_pixels 151,200, planted N=16 with pos-rate ~0.2) while owing it no labels, and it must contain inserted-picture needles with matched distractors. No gradient ever flows through the gate (BCE on fixed labels), the gate is exactly binary at every N, the reader stays frozen, and the question stays in the prefix; the relational extension (a second anchor head composed by the HiMu Seq rule, zero extra forwards) is built only if the pre-registered trigger on the synthetic anchored cell fires. Four weeks, ~45-55 GPU-h in total, every row traceable to a run dir under outputs/scaleup/.

CALIBRATION: How many to keep = the number of blocks whose logistic score exceeds 0; no top-k, no budget, no softmax or quantile across blocks, no attention mass, no answer-derived k. The rule is N-invariant by construction because the score is a function of (prefix, frame) only: inside a fenced block with a per-block position reset the slot state is the same tensor whatever N is, so the threshold cannot dilute (the record: per-task accuracy at N=64 equals N=16 to the third decimal, pooled 0.990 vs 0.989; same-haystack N16->N64 transfer AUC 1.000; the share law k e^s/(k e^s+N-k), e^s = 1.94 at L20, governs the unfenced read's attention mass and never enters the gate). What does grow is the expected number of false blocks, (1-spec)(N-k) ~ 0.01(N-k): measured 0.05 -> 1.18 per question from N=8 to 128 and tolerated by the packed read (rows with false frames only 0.69-0.75, exact-set rows 0.886-0.897 at every N); the paper reports this leak curve (read accuracy vs false blocks at each N) instead of per-frame accuracy alone. Cross-dataset calibration is where the record says the danger is: the HERBench-label gate scores VNBench ret_edit1 at AUC 1.000 but specificity 0.766 (pooled spec 0.80 / recall 0.69), i.e. the bias and the z-scoring, not the direction, fail across prompt formats; hence mu, sd and b are fitted on the synthetic captures made in the target's prompt template (4-option MCQ, question-first, no system prompt) at the target's max_pixels and at planted N=16 with pos-rate ~0.2, and at most one scalar (b) is refit on the synthetic held-out N=64 split to the balanced-accuracy optimum, never on a benchmark. Pre-registered bands on VNBench with no refit: specificity >= 0.985 and recall >= 0.98 pooled at N=16 and N=64, which keeps false blocks at ~1% of fillers (the regime the two-pass read is measured in). The model's own yes/no (AUC 0.92-1.0, exact set 0.78 with the within-question max-2-log-odds rule) and the attention mass remain reported as the label-free rankers that cannot threshold, not as the gate.
CROSS-FRAME: The per-frame gate stays the only gate; relational relevance is measured inside the synthetic set and the extension is built only if a pre-registered trigger fires. (1) Anchored questions ('what is shown right after the secret word X', 'which clip comes immediately after the landmark'): both anchor and target are question-mentioned needles, so the per-frame gate is expected to keep both and the packed two-pass read resolves the order (E ordering on VNBench 0.99; two-pass ordering 0.95 circular at N=256). Trigger: on the synthetic anchored cell, two-pass accuracy with the synthetic gate < 0.70 while the oracle two-pass >= 0.85, or hop-2 recall < 0.90 -> add the HiMu Seq composition (two heads A/B on the same L20 slot, keep_B(t) only if some earlier block passed A; zero forwards; ~3.6k extra params; labels by construction), ~2 GPU-h to re-evaluate; otherwise nothing is built and the limitation is written. (2) Duplicates / 'how many times': every copy is its own block and the gate keeps every copy (no cosine de-duplication: DART arXiv:2502.11494 / ReQuest NMS would delete exactly the countable copies); at >1 fps the needle-second merge rule (--merge-kept-runs, one frame per NEEDLE_DUR window) collapses sampled runs, not distinct needles 1 s apart. (3) Absence / negation: all options sit in the prefix; k=0 questions teach the gate to keep nothing; the read answers from an empty or near-empty kept set (the k=0 arm is reported separately and capped at ~15% of the mix so the read does not learn 'not shown' as a prior, UVQA over-refusal 0.50). (4) Set-valued aggregates where every frame is evidence (MMReD where_spend / rooms_visited, HERBench MPDR / AC k>=2) are the aggregation k-wall, not a gating problem, and no selector helps; stated with the per-task table from the lens-4 taxonomy. (5) What this concedes: no benchmark we evaluate contains a task where a frame's relevance exists only through another frame's content (HERBench AG* are text-answerable: T 1.00 / 0.92 / 0.67); the gate's generality beyond self-evident needles is tested only on our constructed anchored cell, which the limitations section says explicitly. The reader-side cross-frame step is the frozen packed read (0.87-0.88 flat; 0.821 circular at N=256), not a trained reader.

# DESIGN professor-soft-vector: Set-Gate: the professor's joint view moved onto the fenced block states, with the significance vector entering pass two only as an exact drop into the packed re-read

Steelman of the proposal. The best version is: (1) produce the significance vector with a per-frame head (not generated text, which rank-orders but never thresholds, record (c)); (2) compute it from a joint view so that a frame's score can depend on other frames (Q3); (3) inject it into pass two as a hard keep/drop, with the confidence itself never entering the reader. Against the record, three facts fix where each part may live. D4 (DIAG, MMReD, 24 qtypes, N=8+16 train, N=32 test): the SAME logistic head on each frame's <|vision_end|> state scores 0.51 (chance) in a joint forward under the official layout, 0.84 in a joint forward question-first, and 0.975 / AUC 0.998 under the fenced question-first scan (0.982 / 0.9987 transferred to N=32; 0.973 at N=128). The joint 7B forward is also the regime the share law describes (a needle frame's L20 mass 0.015 → 0.003 from N=8 to 128): a vector read off a joint forward is read off a representation that dilutes with N, and the joint forward costs ~77x the attention FLOPs of the fenced scan at N=256 (46,592-token sequence vs 256 blocks of 332 tokens). So the joint view cannot be the 7B's own forward over frames; it can be a small set module over the N fenced block states, which see the question (prefix) and are N-invariant by construction (0.989 at N=16 = 0.990 at N=64 to the third decimal). SOFTGATE: any soft use of the vector inside a pass over all N frames (attention bias, PASTA-style post-softmax reweighting with alpha = 0.01 and row renormalisation, a scaled embedding) is a finite-B gate: the read's count = k + (N-k)/B to the unit, and a reader retrained under it calibrates to the residual (the B=128 reader is 107/107 under the hard gate, i.e. it became a block counter). Only an exactly-zero residual is N-invariant, so the vector may enter pass two only as keep = [s_i >= 0.5]. Week-3 variant 2: the SAME kept frames with ZERO fillers but spread to their original positions fall from 0.79 (packed) to 0.17 at k=5-6, N=128 (pooled 0.880 → 0.819); so "run the model on the frames again" at original positions is dead even with a perfect vector: pass two must be the packed re-read (0.881/0.873/0.871/0.866/0.880 at N=8..128, frozen, no KV retention). What survives: the joint view, as a ~2.2M-parameter set scorer over the N layer-20 block states, residual on the existing per-frame probe (s_i = sigmoid(z_i + Delta_i), Delta zero-initialised so the module starts at the 0.989 gate), trained with BCE on construction labels (no human, no stronger LLM), thresholded at 0.5, feeding the unchanged packed re-read. Its measurable target on the official benchmark already exists: D4's anchored MMReD family ("when B first appeared" / char_on_char / room_on_char) is the only family the pointwise probe scores at 0.82-0.92 while needles and counts are >= 0.96; VNBench has no relational cell (lens 4), so a second, constructed anchored-needle cell with decoys is the stress test. The cheap settling experiment is CPU-only on existing captures.

CALIBRATION: keep_i = [s_i >= 0.5] where s_i = sigmoid(z_i + Delta_i) is a BCE-trained posterior; no top-k, no budget, no quantile, no cumulative-mass rule, no per-question max rule (the record's "within 2 log-odds of the best" needs k >= 1 and fails at k = 0). Why it is N-invariant: (i) z_i and the block states are computed in a forward of prefix + ONE frame, so nothing in them carries N (measured: per-task accuracy at N=64 equals N=16 to the third decimal, 0.990 vs 0.989; spec 0.989 flat, false blocks per question = 0.011 x (N-k), linear as the flat spec predicts); (ii) Delta_i is a residual that is zero unless the labels require cross-frame information, so on the 7 non-relational VNBench tasks the rule reduces to the measured gate; (iii) the module's own softmax over N+1 keys is trained to produce a large anchor-vs-filler logit gap (unlike the frozen backbone whose gap e^s ~ 1.9 at L20 is fixed and gives the share law), the NULL token absorbs the fillers' attention, and relative-time PE makes N=128 look like N=16 positionally; (iv) the module is trained at N <= 16 and tested at 32/64/128 with the pre-registered check that per-frame precision, recall and false blocks per question at N=128 match the pointwise gate's on non-relational tasks within 0.2 pt and that the anchored family's false blocks per question are flat in N rather than ~rho N. Every label-free rule in print (Twilight top-p, AttnComp P=0.95, ParallelComp tau + fixed count, TARG keep-rate quantile, DAFS/ReQuest top-K) presumes a keep fraction, which is k/N, the quantity that dilutes; the thresholded BCE posterior on fenced inputs is the one rule that carries no N, and the gate-threshold-vs-N measurement is unclaimed in all 25 verified gate papers.
CROSS-FRAME: The set scorer is the only place where a frame's score sees other frames, and it sees them through the backbone's own question-conditioned block states, not through the backbone's attention (which dilutes) or through raw frames. Classes, following the lens-4 taxonomy checked against core/mmred.py evidence_frames: (1) anchor-relative ("the frame after X", MMReD char_on_char_* / room_on_char_* / "when B first appeared", the constructed anchored needle): learned by the 2-layer encoder with relative-time PE — the fallback that is N-invariant by construction is HiMu's Seq composition with two pointwise heads, s_B(t) * max_{j<t} s_A(j), zero extra forwards; (2) absence / "which did NOT happen" (HERBench FAM/FOM): all options are in the prefix, the pointwise gate fires per true option, elimination is the packed reader's job — no set logic needed; (3) order-relative (VNBench ord_*, HERBench TSO/ASII): every needle is self-evident and order is done by the packed read (ord 0.99/0.99/0.96 at N=128 behind the fitted gate), no set logic; (4) duplicates / "how many distinct" (VNBench Counting-E2): labels keep EVERY copy, so the module is trained NOT to suppress repeats (no NMS, no cosine merging — EFS/Vgent-style dedup would delete what counting must count); distinctness is the reader's job over the packed copies; (5) identity / set-valued aggregates where every frame is evidence (MMReD where_spend, rooms_visited, spend_*, HERBench MPDR/AC): not a gating problem — the gate is a no-op by design and the k-wall row reports it. Duplicates and jointly necessary frames are exactly where leave-one-out pseudo-labels give ~0 (Nematov; CSM states the additive approximation), which is why the set scorer trains on construction labels and not on reader-counterfactual ones.
