# DESIGN native-trainingfree: NAV gate: Null-Anchored Verdict gate (the frozen model's own per-block yes/no, in the fenced scan, calibrated by a foreign-null anchor and the question's own peak; zero trained parameters)

Keep the pipeline exactly as it is (batched fenced scan with the question in the shared prefix -> keep decision -> frozen packed two-pass re-read) and replace the trained L20 logistic probe by a readout the backbone already produces: the first-answer-token log-odds s_i = logsumexp(yes spellings) - logsumexp(no spellings) of the per-block judge line "Does this frame contain evidence needed to answer the question above? Answer yes or no." appended after frame i inside its fenced block. This readout exists in code (`core/fastpath.py::fenced_forward(judge_ids=..., judge_vocab=...)`, parity-tested 2026-09-30) and on the record it RANKS needles almost perfectly (unfenced D regime on VNBench, 9,034 units: per-task AUC 0.91-1.00, pooled 0.937; `outputs/scaleup/vnbench/qwen2.5-vl-7b/s1u_unit/D_frame_lo/20261010_225007_D-frame_reslo/report.txt`); what failed in the record is calibration (literal "yes" keeps 13% of needles; one global threshold gives recall 0.49 at spec 0.99). The design fixes calibration with two in-model anchors computed in the same scan: (1) a NULL anchor s_null = median verdict over three fixed foreign natural frames (frames from a video outside every benchmark) appended as three extra blocks per question, which estimates the question's own haystack baseline without labels (the dummy-document / content-free-input precedent: Found in the Middle 2406.16008, ICR 2410.02642, Calibrate Before Use 2102.09690, OccamToken 2605.29657, ReQuest 2607.01737); (2) a PEAK anchor s_max = the best frame of the question. The midpoint rule keeps frame i iff its verdict is closer to the peak than to the null, i.e. s_i - s_null >= (s_max - s_null)/2, and declares k = 0 when no frame beats the null by m0 = 2 log-odds. Every quantity is block-local (prefix + one frame + 27 judge tokens, identical token set at every N), so the threshold cannot dilute with N; the only N-dependence is the sqrt(2 ln N) extreme-value drift of a weak peak, which is measured, not assumed. The count k is emergent (no budget, no top-k, no NMS: duplicates are kept for the reader to count), the re-read sees an exactly-zero residual, and the same scan still captures the L20 slot states, so the timestamp-supervised probe (0.989/frame) and the label-free NAV gate are compared on identical frames at no extra GPU cost: the label-source ablation the peers asked for.

ARCH module: NullAnchoredVerdictGate: a ~60-line CPU function over `FastResult.judge_logits[N+3, 6]` -> keep flags [N]. Steps: s_null = median(s_{N+1..N+3}); g_i = s_i - s_null; g_max = max_i g_i; if g_max < m0: keep = all False (k = 0); else keep_i = [g_i >= g_max / 2]. No NMS, no merge, no top-k. The judge line is the stage-2b wording unchanged; the read pass keeps the paper's prompt byte for byte (the gate pass is a separate prompt and the method section says so).
 params: Zero trained parameters. Two pre-registered scalars: rho = 1/2 (the midpoint; a convention, not fitted) and m0 = 2 log-odds (odds ratio 7.4) for the k = 0 declaration; the sensitivity over rho in {0.3, 0.4, 0.5, 0.6} and m0 in {1, 2, 3} is reported from the stored judge logits (CPU) and never tuned per task, N or benchmark. Three fixed null frames stored under data/ (committed, not drawn from any benchmark).
 plugs_in: Replaces the keep callable of the batched path. Because the rule needs all N scores (peak anchor) it cannot decide per chunk as `load_gate`'s keep(states, first) does; instead `evaluate.py --two-pass --gate judge` runs `fenced_forward(frames + nulls, keep=None, decode=False, capture_layers=[L20], judge_ids=JUDGE, judge_vocab=V)` (all blocks encoded, no KV retained: the two-pass read never needs the scan's cache), applies NullAnchoredVerdictGate on CPU, writes `kept` to eval.csv exactly as the fitted gate does, and hands the kept frames in time order to `two_pass_read` (packed, official layout, frozen decode). `gate_capture.py --fast --judge TEXT --nulls 3` stores J next to X so the probe and NAV are scored on the same frames. The dense fenced path (Gemma / InternVL) gets the same judge through `core/fence.greedy_decode`'s mask + a judge tail, at N unbatched forwards (not in the 4-week scope).
 cost: Per block the judge adds ~27 tokens on top of a ~195-token block (mp151200) or ~330 (native 512 px): +12-15% FLOPs per block (the full 28-layer stack already runs in the scan; nothing is truncated). Plus 3 null blocks per question. N=128: scan 131 block forwards + 131 judge mini-forwards in 2 chunks of chunk_tokens 16,000, ~1.16x the current scan's FLOPs, re-read unchanged (k ~ 3-6 packed frames + <= 24 decode steps) -> ~1.14x the current scan + re-read in tokens, same forward count structure (+3 blocks). N=256: 259 blocks, ~1.15x the current scan + re-read. The supervised probe's slot states come out of the same pass, so the label-source ablation is free. Memory: the judge tail appends 27 tokens to the chunk cache; negligible.
TRAINING: None. No gradient, no probe fit, no distillation. The ranking is the backbone's own verdict; the calibration is two anchors computed inside the same scan. | labels: None for the gate. The two scalars (rho = 1/2, m0 = 2) are pre-registered conventions; their sensitivity curve is read off stored judge logits against (a) the held-out VNBench timestamp labels for the paper's diagnostic plot and (b) the two-pass answer accuracy on <= 100 fold-A training questions (gold answers only) as the label-free check that the convention is not pathological. If the paper reports any scalar chosen on data, it says 'one scalar chosen on M = 100 question-level answers, no frame labels' (Lens 5 wording). | data: VNBench planted and official-uniform splits already on /rg (fold A/B by haystack, `sbatch/lib/splits/qids_vnbench4_fold{A,B}.txt`), MMReD seq_len_8/16/32 (incl. answer-0 cells for the k = 0 test), HERBench TSO/SVA isolated N=8..128 for the real-footage limit. Three foreign-null frames added to data/ once. | gpu_h: 0 for training. All GPU time is inference: the scan cost above (~1 GPU-h per 20K blocks at mp151200 on an A100-40GB / rtx6k, from the week-1 captures), i.e. the first experiment ~4 GPU-h, the full method rows ~25 GPU-h (see plan).
CROSS-FRAME: By over-keeping plus the joint re-read, never by the gate reasoning across blocks. The judge line asks whether the frame holds evidence NEEDED for the question (not whether it answers it), and the question with all its referents sits in the prefix, so for anchor-relative questions ('what happens after the red car appears') the verdict fires on frames showing either referent; the packed re-read sees the kept frames in time order and resolves after/before/first/last (the two-pass read already does ordering at 0.744 circular vs plain 0.518). For 'how many distinct objects' with duplicates: no NMS and no run-merge in the gate, every appearance is kept, de-duplication is the reader's job (its ceiling, counting inside images 0.21, is a reader wall, not a gate wall). For 'which did NOT happen': the options are in the prefix, the verdict fires per depicted option, the reader eliminates. For MMReD every-frame qtypes (where_spend, rooms_visited): all gains sit near g_max, the midpoint keeps everything, the gate is a no-op and the read is the plain read, which is the correct behaviour where relevance is not sparse (Lens 4: that is the k-wall, not a gating problem). Structural blind spot, stated in the paper: relevance that exists only through another frame's appearance (anchor-via-appearance); Lens 4 finds no such task in VNBench, HERBench-lite or MMReD, and the HERBench AG* rows are text-answerable. The label-free extension if it is ever needed is a second scan whose prefix is question + round-1 kept frames (Beam Retrieval / MDR template, 2N blocks), judged by the same NAV rule; not proposed within the four weeks.
CALIBRATION: Midpoint-between-anchors on block-local log-odds. Per question: s_null = median verdict of 3 fixed foreign-null blocks; g_i = s_i - s_null; g_max = max_i g_i. Declare k = 0 iff g_max < m0 (= 2 log-odds: no frame makes 'yes' 7.4x more likely than a content-bearing irrelevant frame does). Otherwise keep i iff g_i >= g_max/2 ('closer to the peak than to the null'). How many to keep is never decided: each frame is judged against two per-question constants, so k emerges, duplicates stay, k = N is allowed, and no quantity k/N, top-k, top-p or Otsu class proportion enters the rule. N-invariance: (i) every s_i and s_null comes from a forward over prefix + ONE frame + 27 judge tokens, the same token set at N = 8 and N = 256, so there is no shared softmax across frames to dilute (the 1/N dilution of negative result (c) is a property of the joint forward only; SSMax 2501.19399 and the record's share law k e^s/(k e^s + N - k) state why post-softmax mass cannot carry a fixed threshold, and a fenced block has no such denominator); (ii) the null anchor is a per-question constant; (iii) the peak anchor equals the strongest needle whenever the needle gain exceeds the haystack extreme, which is N-free; when needles are weak the haystack maximum grows like sigma_h * sqrt(2 ln N) (about +1.3 sigma_h from N = 8 to 256), the one logarithmic N-dependence, which the first experiment measures as kept-count vs N on identical questions. Contrast with the record's rule 'within 2 log-odds of the best' (recall 0.95 / rejection 0.90 on ~2 stored negatives per positive, exact set 0.78): that rule has only the peak anchor, so it cannot represent k = 0 and its window is an absolute 2 regardless of how far the question's haystack sits below the peak; the null anchor supplies the missing scale.
AVOIDS: (a) SELFGATE: answer-loss-only ST-Gumbel gate never closes (mean gate bit 1.000; closed blocks are gradient black holes; in-window loss satisfiable without gating): Nothing is trained and no gradient exists: the gate is a thresholded readout of the frozen model, so there is no closed-draw black hole and no 'closing never pays' incentive problem. The forward is exactly binary by construction (dropped frames are absent from the re-read). || (b) SOFTGATE: finite-penalty soft gates make the reader calibrate to residual mass (pred = k + (N-k)/B), gate-trained reader becomes a content-blind block counter: Hard keep/drop followed by the packed two-pass re-read: the reader never sees a residual, and the reader is frozen (no LoRA on VNBench), so no calibration to a residual can form. This is also the digest's Lens-8 cure (frozen reader: SeerAttention, LKV, WG-KV, TSPO, ReFoCUS). || (c) Self-gate on attention MASS refuted by the share law (threshold fit at N=8 hides all evidence at N>=32); the model's own verbal yes/no ranks (AUC 0.92-1.0) but literal 'yes' keeps 13% of needles and the within-2-log-odds rule leaks 10%: The score is not attention mass and is not computed in the joint forward: it is the verdict log-odds inside a fenced single-frame block, which has no N-dependent softmax denominator. The calibration failure of the verbal verdict is addressed, not repeated: the absolute 'yes' threshold is replaced by a per-question null anchor (handles the task-dependent offset: on VNBench ordering tasks P(yes) on needles is 0.00-0.10 yet AUC is 0.98-0.99, i.e. needles are 'less no', which only a relative rule can read) plus a peak anchor (the half of the record's rule that worked), and the leak is measured against the N-k haystack, not the ~2 stored negatives of self_gate.py. || (d) QGATE: question-blind block encodings do not expose relevance (AUC 0.5-0.7); the gate signal needs question-conditioned blocks: The judge runs in the fenced question-FIRST layout: the question is in the shared prefix and the block attends to it; the judge line then asks about 'the question above'. No cacheable question-agnostic encoding is claimed. (The record's D regime that gave AUC 0.91-1.00 had the question AFTER the frame, so the in-prefix verdict on VNBench is the one unmeasured link; it is the first experiment's kill criterion.) || (e) The fenced read is blind to order and count (0.48 flat); frozen-reader counting ceilings (k > 4: 0.58-0.69; inside images 0.21): The read is untouched: the unfenced packed two-pass re-read (0.87-0.88 flat; circular 0.677 at N=64) consumes NAV's kept set exactly as it consumes the probe's. The counting ceilings are reported as reader walls; the gate keeps duplicates (no NMS/merge) so it never subtracts from the count the reader could reach. || (f) Literature: trained set-level selectors, selection neutral/harmful for counting, untrained self-gating weak in print, Sparse RAG = supervised P('yes') twin, Superposition Prompting = training-free top-k twin: NAV is neither a budgeted ranker nor a trained gate: it is a thresholded, cardinality-free, label-free in-model gate, the cell Lens 1/5 found empty ('every label-free method ends in top-k or a budget'; 'null-frame calibration of a frame gate in a VLM: no precedent'). # DESIGN relational-set-gate: Residual Set Gate (RSG): a 2M-parameter relational gate over the fenced scan's per-block states, residual on the 0.989 probe, with non-softmax message passing over hard candidates

Keep the pipeline exactly as it is (fenced scan -> gate -> frozen packed two-pass re-read) and replace only the keep decision. Instead of thresholding each block's layer-20 <|vision_end|> state alone, the N slot states plus the prefix's question-end state at the same layer are handed, after the whole scan, to a small ordered-set module that outputs keep/drop per block. The module is RESIDUAL on the existing logistic probe: keep_t = 1[p_t + Delta_t > 0], where p_t is the frozen probe logit (the record's 0.989/frame gate) and Delta_t comes from two layers of sigmoid-gated, unnormalised message passing over the candidate set C = {t : p_t > tau_low}, with a relative-time bias in seconds, a question token and a learned null token. At initialisation Delta = 0, so the gate IS the current gate and every change is measurable against the record; non-candidates contribute exactly zero (the record's own SOFTGATE lesson: only an exactly-zero residual is N-invariant), and the aggregation has no softmax row normalisation, so the messages do not obey the share law that dilutes attention mass as 1/N. It is trained offline by BCE on labels by construction (VNBench needle_time intervals, already captured at N=16/64, plus synthetic composites spliced into the existing frame pools: duplicates vs distinct, right-after-X, k=0 displaced questions, foreign distractors labelled 0), never by the answer loss, with the reader frozen. What it buys on the record: (i) under the official uniform grid the per-frame gate keeps needle RUNS (14.5 / 28.9 blocks for 2.9 needles at N=128/256) and counting pays (cnt_edit1 0.84 vs 0.98 with one frame per needle; k=5-6 0.63 vs 0.79); a content-aware run representative fixes this without swallowing back-to-back needles 1 s apart, which a naive adjacency merge does; (ii) the probe's false positives (0.16 -> 0.81 per question from N=16 to 128 planted, exact set 0.94 -> 0.90) are decided with the within-question context the record shows nearly works label-free (within 2 log-odds of the best: 95% kept / 90% rejected); (iii) the relational classes the peers named (duplicates vs distinct, anchor-relative, absence) become representable, and the gate's precision/recall is reported per frame as a function of N, which no paper in the digest does. Cost is zero extra frame forwards; the gate is about 10^-6 of the scan's FLOPs and under the uniform grid the re-read shrinks from about 5,400 to about 900 tokens at N=256.

ARCH module: Deferred set gate over the ordered candidate set. (1) Candidate pre-filter: C = {t : p_t > tau_low}, tau_low fitted once on the training fold for recall >= 0.999 of labelled frames (the deployed probe at tau = 0 already has fn 0.01 flat to N = 128, so tau_low sits a few logits below 0; expected |C| = k + a few probe false positives, about k + 1 at N = 128 planted, k + runs under uniform). Blocks outside C are dropped with no message (exact zero) and never enter the module. (2) Tokens: h_t = LayerNorm(Linear(3584 -> 256))(z(x_t)) + phi(p_t), one question token h_q from q through the same projection, one learned null token. (3) Two message-passing layers, d = 256, 4 heads, FFN 512, pre-LN, with sigmoid-gated unnormalised attention: m_t = sum_{s in C u {q, null}} sigmoid(a_ts) W_v h_s, a_ts = (W_q h_t . W_k h_s)/sqrt(d_h) + B(dt_ts) + c_h, where B is a learned bucketed bias on the signed time difference in seconds (buckets -inf..-30, -30..-10, ..., -1..0, 0, 0..1, ..., 10..30, 30..inf), so before/after and same-second adjacency are visible and nothing depends on the absolute index or on N; a per-head learned offset c_h initialised at -4 makes every message near zero at init. The null token's final state is not read out (no cardinality head): the k = 0 case is handled by every candidate's Delta_t going negative, which the null token's messages make expressible.

(3) Anchor-relative ('what appears right after X'): the target candidate attends to anchor candidates through the signed time bias (after = negative dt bucket) and the question token names X; anchor + target are kept, the other needles dropped, so the read gets 2 frames instead of 4; on VNBench proper this never binds (the per-frame gate keeps all 4 and the reader orders at 0.98/0.94/0.88), so it is a constructed cell, reported as such. (4) Absence and negation: 'which did NOT appear' is handled by keeping the frames of the options that did appear (per-frame suffices; the set context calibrates when 3 of 4 appear); k = 0 is handled by the null token plus T5 items (all candidates pushed negative), evaluated on synthetic and HERBench FAM/FOM only, since VNBench has no k = 0 question and no 'not shown' option. (5) Set-valued aggregates where every frame is evidence (MMReD where_spend / rooms_visited, HERBench MPDR / AC): no selector helps, the gate is a no-op by design, and the paper says so with the per-task table: that is the k-wall of the read, not a gating problem. The relational information travels only between hard candidates and only through unnormalised sigmoid messages; fillers outside C never speak, which is what keeps (1)-(4) from degrading as N grows.
CALIBRATION: How many to keep is never a budget, a top-k or a top-p: it is the sign of a per-block logit, keep_t = 1[p_t + Delta_t > 0], trained by BCE on construction labels, the same rule as the deployed probe and as Sparse RAG's fixed sigma on P(yes); k is whatever the signs say, 0 included. N-invariance holds by construction at every stage, not by fitting at one N: (i) p_t is computed from a fenced block that sees the prefix and itself only, so the share law k e^s/(k e^s + N - k) (e^s = 1.94 at L20, the quantity that refuted thresholding attention mass) does not apply; the record shows the probe's accuracy identical at N = 16 and 64 and its miss rate 0.01 flat to N = 128. (ii) Delta_t is a sum of sigmoid-gated messages, not a softmax row: no normalisation across blocks, so a needle's message to another needle is the same whether 10 or 250 fillers exist; fillers outside C contribute exactly zero rather than a diluting residual, the SOFTGATE lesson applied inside the gate. (iii) No absolute index, no N feature: time enters only as signed differences in seconds through bucketed biases, so the function is defined identically at any N and any fps. (iv) The only N-dependent quantity is |C|, the probe's false positives (about 1 per cent of N) plus runs; the training set spans N = 16, 64 and 128 and |C| per question is reported at every N up to 256 with the gate's per-frame precision/recall, so drift, if any, is measured rather than assumed. (v) Within-question relative information, which the record shows nearly suffices label-free (within 2 log-odds of the best: 95 per cent kept / 90 per cent rejected, exact set 78 per cent; top-k with the true k 94 per cent), is available to the module through the messages, but it is anchored by the absolute labelled threshold of p_t, so k = 0 and k = N do not break it as the relative rule alone does. Zero-init of Delta guarantees the deployed calibration cannot start worse than the record's.

# DESIGN two-round-anchor: ANCHOR2: two-round fenced gating, round 2 = a second fenced scan whose shared prefix holds the question AND round-1's kept frames (with timestamps), scored by a second logistic probe on the layer-20 block state

Round 1 is the measured pipeline, untouched: fenced scan (prefix = question), logistic gate g1 on the L20 vision_end slot state (held out by haystack 0.9951/frame, AUC 0.9993; N16-to-64 transfer 0.9992), kept set K1. Round 2 fires iff the merged anchor count A = |merge_kept_runs(K1)| is in 1..8: a second batched fenced scan of ALL N frames whose shared prefix is [question] ['Reference frames:'] [<time> anchor_1] ... [<time> anchor_A] (anchors at their natural prefix positions; the prefix KV is computed once and expanded over the chunk batch exactly as the question prefix is today) and whose blocks are [<time caption> frame_t] under the per-block position reset; a NEW logistic probe g2 on the round-2 L20 slot state decides keep/drop per block at threshold 0; the final set K = K2 is read by the unchanged frozen packed two-pass re-read in the official layout, and the model generates the answer. Round 2 makes relevance-given-the-anchors decidable per block, because the frozen model's own attention from the block to the anchors' KV does the conditioning (no relational module): 'the item right after X' becomes (same class AND t > t_X), 'the item the clue names' becomes (matches the content of the clue frame now in the prefix). Training is BCE on per-frame labels by construction (anchored questions written over the existing 450 VNBench ord_* videos, whose needle times and item names are in meta), fit on CPU in seconds; nothing is trained inside the backbone, no gradient ever crosses a gate, the reader is frozen. Cost 2N block forwards plus one short prefix forward, about 2x the current scan tokens, still O(N) and N-free per block. Exactly two rounds; no fixed-point iteration.

CROSS-FRAME: Taxonomy (lens 4) and what ANCHOR2 does with each. (1) Anchor-relative time ('right after / before X', VISTA Two-Needle, Ego4D NLQ before/after): round 1 keeps every frame of the named class (all 4 needles: the pointwise optimum); round 2 puts the anchor with its time in the prefix and a time caption on every block, so g2 can read (class AND t > t_anchor) per block; K2 = anchor + later needles (<= 4 frames); 'nearest' is left to the packed read, which orders <= 4 kept inserted images at 0.97-0.99 (two-pass ord_insert1/2, every N). (2) Target identifiable only through an anchor's content (VideoChat-Flash clue chains, MDR hop 2): round 1 fires on the clue frame (pointwise visible) but is blind to the target; round 2 exposes the clue's content to every block through the prefix, so g2 scores 'matches what the clue names' per block. This is the one class a per-frame gate cannot represent at any threshold and the class where the multi-hop NIAH gap lives (99.1 single-hop vs 31.3/25.4 multi-hop, VideoChat-Flash). (3) Absence / 'which did NOT happen' (HERBench FAM/FOM): all options are in the prefix already; round 1 fires per true option and the reader eliminates; round 2 adds nothing and is expected to reproduce K1 (part of the no-harm check). (4) Duplicates / 'how many distinct': NOT a round-2 job. Round 1 keeps every copy; de-duplication is a read-format question (enumeration with frame identifiers, lens 6) and g2 is trained to keep duplicates (label 1), never to drop them (DART/NMS-style pruning deletes what counting must count). (5) Every-frame aggregation (where_spend, rooms_visited, MPDR, RLPC 'All'): no selector helps; the trigger (A > 8) skips round 2 and reads K1; this is the k-wall, reported as such. Mechanism: no new relational module; the conditioning is the frozen model's own cross-attention from the block to the anchors' cached KV, the same mechanism that makes question-conditioning work (QGATE: question-blind blocks are chance, question-in-prefix blocks are 0.99). Exactly two rounds: our constructions and the clue chains are one hop; VideoAgent's rounds give 53.8 / 58.6 / 60.2 / 59.8 (saturation at 3, -0.4 at 4); Beam Retrieval needs a score threshold tau to stop a variable chain and MDR fixes n=2; a third round would re-use g2 with K2 as anchors and is left out of this design.
CALIBRATION: 'How many to keep' is never decided: each block is kept iff g2's logit on its own L20 slot state exceeds 0, a per-frame decision with no top-k, no budget, no cumulative mass and no per-question quantile. It is N-invariant by construction because the round-2 block is scored inside a forward of [prefix_2 ; caption ; frame] whose length depends on A (1..8 anchors, bounded by the trigger) and never on N: there is no softmax over the N frames anywhere in the decision, so the share law k e^s / (k e^s + N - k) (e^s = 1.94 at L20 on the plain read) cannot dilute it; this is the same property that made g1's threshold fitted at N=16 hold at N=64 (0.9992) and the two-pass read flat 0.88 from N=8 to 128. Cross-question calibration across A (the prefix length varies 1..8) is handled by fitting g2 on rows spanning A = 1..8 with per-fit z-scoring, and k=0 target sets (anchor last/first, 'None' answers) are in the training mix so the probe has a correct 'keep only the anchor' mode. The kept count follows from the labels: for 'right after' it is 1 + (needles after the anchor), 1..4 on VNBench; the reader resolves the rest. The only code-side rule besides the two thresholds is the trigger 1 <= A <= 8 (merged 1 s runs), which bounds the prefix and sends every-frame questions straight to the read.

CALIBRATION: How many to keep = the number of blocks whose logistic score exceeds 0; no top-k, no budget, no softmax or quantile across blocks, no attention mass, no answer-derived k. The rule is N-invariant by construction because the score is a function of (prefix, frame) only: inside a fenced block with a per-block position reset the slot state is the same tensor whatever N is, so the threshold cannot dilute (the record: per-task accuracy at N=64 equals N=16 to the third decimal, pooled 0.990 vs 0.989; same-haystack N16->N64 transfer AUC 1.000; the share law k e^s/(k e^s+N-k), e^s = 1.94 at L20, governs the unfenced read's attention mass and never enters the gate). What does grow is the expected number of false blocks, (1-spec)(N-k) ~ 0.01(N-k): measured 0.05 -> 1.18 per question from N=8 to 128 and tolerated by the packed read (rows with false frames only 0.69-0.75, exact-set rows 0.886-0.897 at every N); the paper reports this leak curve (read accuracy vs false blocks at each N) instead of per-frame accuracy alone. # DESIGN professor-soft-vector: Set-Gate: the professor's joint view moved onto the fenced block states, with the significance vector entering pass two only as an exact drop into the packed re-read

Steelman of the proposal. The best version is: (1) produce the significance vector with a per-frame head (not generated text, which rank-orders but never thresholds, record (c)); (2) compute it from a joint view so that a frame's score can depend on other frames (Q3); (3) inject it into pass two as a hard keep/drop, with the confidence itself never entering the reader. Against the record, three facts fix where each part may live. D4 (DIAG, MMReD, 24 qtypes, N=8+16 train, N=32 test): the SAME logistic head on each frame's <|vision_end|> state scores 0.51 (chance) in a joint forward under the official layout, 0.84 in a joint forward question-first, and 0.975 / AUC 0.998 under the fenced question-first scan (0.982 / 0.9987 transferred to N=32; 0.973 at N=128). The joint 7B forward is also the regime the share law describes (a needle frame's L20 mass 0.015 → 0.003 from N=8 to 128): a vector read off a joint forward is read off a representation that dilutes with N, and the joint forward costs ~77x the attention FLOPs of the fenced scan at N=256 (46,592-token sequence vs 256 blocks of 332 tokens). So the joint view cannot be the 7B's own forward over frames; it can be a small set module over the N fenced block states, which see the question (prefix) and are N-invariant by construction (0.989 at N=16 = 0.990 at N=64 to the third decimal). SOFTGATE: any soft use of the vector inside a pass over all N frames (attention bias, PASTA-style post-softmax reweighting with alpha = 0.01 and row renormalisation, a scaled embedding) is a finite-B gate: the read's count = k + (N-k)/B to the unit, and a reader retrained under it calibrates to the residual (the B=128 reader is 107/107 under the hard gate, i.e. it became a block counter). Only an exactly-zero residual is N-invariant, so the vector may enter pass two only as keep = [s_i >= 0.5].
