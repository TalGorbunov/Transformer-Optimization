## Context

real-video aggregation regime next to MMReD: real haystacks 10–170 s, synthetic needles with exact
timestamps, 9 subtasks on the retrieval / ordering / counting axis, k ≤ 6. Before any method cell the
UNIT rule applies (`docs/UNIT_BASELINE_2026-10-06.md`): first measure, per task, whether the frozen
model can read ONE needle when handed it (E), whether it recognises a needle as relevant (D), and the
text-only floor (T). On HERBench that baseline split the tasks into perception walls vs method targets;
on MMReD it showed "perception perfect, aggregation wall". VNBench's expected profile is the MMReD one on

| fact | value |
|---|---|
| rows | 5,400 = 1,350 videos × `try` 0–3 (same question, options permuted; `gt_option` A–D) |
| keys | `video` ("./VNBench/<stem>.mp4"), `question`, `options` (4; **ints** for cnt_*), `needle_time` (list of **integer** start seconds, one per needle), `gt`, `gt_option`, `length` (s), `type`, `try` |
| subtasks (150 videos each) | ret_insert1 / ret_insert2 / ret_edit1 (k = 1) · ord_insert1 / ord_insert2 / ord_edit1 (k = 4, answer = the order) · cnt_insert1 / cnt_edit1 (k = 1–6, `gt` = len(needle_time)) · cnt_edit2 (4 inserted images with 1–4 objects each, `gt` = total 4–16 = count-within-unit then sum) |
| needle kinds | **edit** = subtitle "The secret word is NAME" over the original frames (names Alice…Zach); **insert** = a full-frame static image replacing the video |
| needle duration | **exactly 1 s from the integer start** (paper; measured on the July frames: visible t+0.23…t+0.77, absent at t−0.03 and t+1.04). The July prep's 1.5 s window over-labelled. |
| timeline | insert needles LENGTHEN the mp4 by 1 s each (edit 34.8 s vs 6-needle insert 40.8 s of the same haystack); `length` = the original haystack length, NOT the mp4 duration; `needle_time` is in the **final** timeline (2nd needle listed at 3 s is on screen at 3.3 s, gone at 4.24 s) → use the decoded container duration, never `length`; never shift; never clamp with `length` (~120 try-0 rows have a needle ending past `length`, all inside the mp4) |
| spacing | min gap 1 s (edit) / 2 s (insert); needles may start at 0 |
| lengths | 10–169.5 s, median 40; 450 / 450 / 450 in <30 / <60 / ≥60 s; haystacks MSRVTT + NExT + ActivityNet, 150 haystacks × 9 items (same footage under 9 types → leakage key = haystack) |
| **naming quirk** | rows with `type` ret_insert1 ("landmark in the picture") sit in files `*_ret_insert2.mp4` and vice versa (150 each); the upstream scorer keys by json `type` and then swaps the two names at report time, i.e. the paper's table uses the FILENAME naming. Rule: **qtype = the filename suffix**, raw `type` kept in `meta.raw_type` (auditable, no swap needed in our tables) |
| official prompt | `f"{question}\nA. {o0}\nB. {o1}\nC. {o2}\nD. {o3}\nAnswer with the option's letter from the given choices directly."` (model_video_niah.py) — structurally identical to `minerva_prompt` (`core/data/mcq.py:72-76`) |
| official scoring | eval.py: strip `_<try>`, a video is correct iff all 4 tries correct; per-type acc → family = mean of 3 subtypes → Overall = mean of families; letter = first A–D found in `pred` after cutting at the first "." (`minerva_extract` would take the LAST letter and misread option text such as "C. Hôpital Notre-Dame" as D) |
| units for a 1 s range | `unit_grid` keeps offsets −1/0/+1 only → the five unit names collapse to two: `frame` (= `clip3_d1` = `clip5_d2`, the midpoint t+0.5) and the 3-frame `clip5_d1` (= `clip9_d2`: t, t+0.5, t+1.0; the two edge frames are frame-rate luck and, with 1 s gaps on edit types, t+1.0 may be the next needle's first frame) |
| published Qwen2-VL-7B | retrieval 69.1 / ordering 12.4 / counting 20.0 (1 fps, 224 px) |

## What the night established

1. **Perception is perfect on VNBench** (regime E, needle frames only): retrieval 0.95–1.00, ordering 0.99, counting subtitles **1.00 up to
   k = 6**, counting inserted images 0.81; the only wall is `cnt_edit2` (count objects inside 4 images, then sum) at chance. T = 0.250 exactly.
   Resolution does nothing. A 3-frame clip unit hurts counting (duplicate views are counted). U* = `frame`.
2. **Detection from the model's own vote is near-perfect per task** (regime D, 9,034 units): AUROC 0.92–1.00, hard = easy. The raw "yes" is
   rare on order/count questions, so a per-task threshold (or a trained gate) is needed, not a global one.
3. **The collapse in N is real on real footage and it is an aggregation collapse.** With every needle planted in view the deployed read falls
   0.84 → 0.69 from N = 8 to 128 while retrieval stays ≈ 1.0; by k: k = 1 flat, k = 2 0.96 → 0.73, k = 3–4 0.73 → 0.53. Under the official
   sampling accuracy rises with N only because needles come into view; the rows that have every needle in view fall 0.93 → 0.69 → 0.65, and at N = 256, where every row has every needle sampled, the official curve itself turns down (0.68 → 0.65).
4. **The fenced oracle gate is flat (0.49–0.53) but cannot order or count the kept blocks** (ordering = chance, counting 0.2–0.4, retrieval
   intact). Decomposition at N = 8: plain 0.84 → question-first 0.59 → fence only (question last) 0.50 → both 0.47 → + gate 0.53. At N = 64: question-first 0.36, fence only 0.37, both 0.21, gate 0.49. Ungated, the fence makes even retrieval fall with N (k = 1 rows 0.91 → 0.67; the landmark needle 0.75 → 0.25) while the oracle gate holds it at 1.00 / 0.99 / 0.93 at every N: the gate's contribution on VNBench is retrieval under dilution and nothing else. The
   per-block position reset erases block order and count by itself; the question-first layout is a second loss that grows with N. The frozen
   reader aggregates only with frames-first + full attention. **The method's READ step has to be trained**; VNBench has no train split.
