# Fixed native-value visual memory: CPU software check

This stage implements and checks one small, question-independent memory core. It releases no vision extraction, decoder integration, optimizer, fitting, task evaluation or GPU work. The ordinary joint LoRA competence result remains a separate dependency. The first later benchmark pilot, if separately approved, keeps the original4,000 MMReD training pairs and original validation/test questions; this check adds no question supervision or data.

Use exactly32 learned slots,128-dimensional keys and native3,584-dimensional values. Each input item is one frozen Qwen postmerger raster token. Supply its zero-based global frame index, raster row/column and merged-grid height/width as int64 vectors. Support frame indices0–127 only. Coordinates are `(frame_index/128, (row+.5)/height, (column+.5)/width)`, with no collection-length or chunk normalization. Encode each coordinate using sine and cosine at frequencies1,2,4,8 with phase2πf coordinate:24 fixed features, ordered frame/y/x, then frequency, then sine/cosine. Native window ordering must be undone upstream before assigning raster coordinates; no image processing occurs here.

Promote native FP16 or FP32 features to FP32. Normalize only the key input by `x / sqrt(mean(x²)+1e-6)`, with no learned RMS parameters. Concatenate the24 position features and apply a bias-free128×3608 key matrix. Scores are `Q Kᵀ/sqrt(128)`, with Q32×128. Values remain the original, unnormalized native features: there is no value or output projection, extra FFN or learned output normalization. Disable enclosing autocast for score/moment arithmetic. The core returns FP32; a future integration owns the single native cast.

Use the unchanged [attention moment accumulator](../../gnnformer/attention_moments.py), SHA `2513044c9ea490098217fc55ac68aac5c798ce3eed7ca746e47a447a3e0fd804`, for stable summary/merge/read. Read normalized values μ and log mass logZ, and form32 native-width tokens `μ + z*d`, where d is one3,584-vector and z is either logZ or exactly zero. Both arms compute and expose the same underlying moments. A private CPU generator at seed24 draws the key matrix uniformly in±1/sqrt(3608), then Q from N(0,1); d is initialized exactly zero. Construction must not consume the caller's RNG. There are exactly469,504 allocated FP32 parameters in three tensors. The normalized arm's d is functionally inactive, so equal parameter shapes do not mean equal effective degrees of freedom. No other configuration or initializer is tried.

At zero d the two readouts coincide exactly. After assigning a nonzero d in a software fixture, repeating every identical enriched item c times leaves μ invariant, adds log(c) to logZ and adds log(c)*d to mass-bearing tokens. Reassigning frame positions is not literal replication. These are known normalized-attention/multiplicity properties, not a novel attention algorithm, object-count interpretation or guarantee that32 slots preserve arbitrary bindings. Normalized means already retain relative frequencies; mass is not presumed necessary for `where_spend` or `spend_together` argmax/min answers. The eventual hypothesis concerns useful aggregation accuracy, with mass as one feature ablation.

Run exactly eight native-width CPU fixture groups: (1) exact seed/draw order, untouched caller RNG and469,504 parameters; (2) independent scalar-position/FP64 softmax reference and raw identity values under zero scores; (3) full versus noncontiguous merge order, item permutation, and gradients with respect to inputs and all three parameter tensors; (4) zero-d arm parity, common live key/query gradients and the expected inactive versus live d gradient; (5) replication values/log mass/token shifts after a fixed nonzero d; (6) global-coordinate preservation and a deliberately incorrect chunk-local reset that must differ; (7) FP16 promotion and FP32 preservation under an outer CPU autocast; (8) empty-chunk identity, empty-read rejection, invalid shapes/dtypes/coordinates/nonfinite inputs and parameters, RMS overflow, invalid state, and rejection of a question argument. Test perturbations are local mathematical fixtures, not fitted initializations. The module accepts no question, answer, target, scene graph or generated prefix.

One CPU Slurm allocation is capped at90 seconds, four cores and16GiB. No model/head/vision calls or optimizer steps are allowed. The four new files are core, test/check entry point, this proposal and the CPU wrapper; inherit only the unchanged accumulator source. Save their hashes and copies before tests, retain unittest failures, and publish the passed summary last only if all eight groups and the time bound pass. Outputs belong under `outputs/native_aggregation_vlm/native_visual_memory/check_JOB`. No tensors or tests execute on the login node. Numerical tolerances are fixed in the test source before execution. A passing result establishes this core's software/algebra behavior only; native cold/cache fidelity, benchmark competence and useful aggregation remain untested.
