Consume only a passed compact-training merge and its exact four balanced shards: 1,000 worlds and 6,200 frame occurrences per shard, 24,800 frames overall. Preserve per-world native batching and image order; do not deduplicate or regroup frames. The fixed 100 training diagnostics reuse these worlds. No validation/test examples, learning, language forward, native head, backward or optimizer are part of harvest.

The CPU release check requires the independent audit of profile443978 to pass all CPU numerical and cold/training components. Explicitly retain original_profile_passed=False and its bound original failure; successful feature ownership and selected component audits do not convert that failed cache-parity profile into a pass. Bind its native model/processor/precision identities, frozen feature function, eight feature timing records and source closure. The check also verifies the completed compact stage, all compact file hashes, original row order, fixed diagnostics and per-world vision shapes. Larger decoder widths remain descriptive and do not prevent harvest: their separate boundary profile and any training release are deferred.

Run a 120-second, four-core16GiB CPU release check before any GPU task. For each shard j define R_j = max(S_profile, S_compact,j) + 1.25 * sum_(N,qtype) 50 * (max_compact_staging_seconds_(N,qtype) + F_N) + 60. Compact maxima use all original CPU staging observations in each cell and include full PNG verification/reprocessing, pixel hashing, compact serialization and verification. This deliberately overcounts some I/O against the old profile and retains every observation. It does not pretend the old feature profile already timed PNG reprocessing. Publish all inputs and each resulting bound. No observed compact timing is invented. A valid but over-budget check publishes resource_eligible=False and releases no GPU work.
