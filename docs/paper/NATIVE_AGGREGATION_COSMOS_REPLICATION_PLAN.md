# Native reasoning replication after the original MMReD pilot

This is a design note, not a job or model release. The available reasoning backbone is Cosmos-Reason1-7B at revision3210bec0495fdc7a8d3dbb8d58da5711eab4b423 through the existing compatibility mirror `cosmos_reason1_compat_440953`. It is not Reason2. The [native interface audit](NATIVE_AGGREGATION_NATIVE_KV_IMPLEMENTATION_AUDIT.md) verifies the compatible Qwen2.5-VL architecture: hidden width3584,28 decoder layers and four KV heads. Actual Cosmos weights, tokenizer, processor, vision features and numerical behavior require their own binding and software check; architecture compatibility does not make Qwen feature caches interchangeable.

Keep the same32-slot memory core and three comparisons: ordinary visual tokens, normalized memory and mass memory. Initially retain the common original4000-question direct-answer training recipe and final-checkpoint selection for all three Cosmos arms. Evaluate each fixed checkpoint under both direct and native reasoning instructions, using the same4096-token ceiling and natural EOS stopping in both policies. A direct answer can finish after its short JSON; every token actually generated still counts. This compares the instruction/format policy within one adapted model without changing its maximum generation allowance; a Qwen-versus-Cosmos comparison cannot establish composition. On prospectively fixed non-test cases, check both unadapted and adapted ordinary Cosmos for useful completed reasoning before interpreting a negative composition result. Direct-answer adaptation may suppress the original reasoning behavior.

The model card requests `<think>...</think><answer>...</answer>` and recommends at least4096 output tokens. Its template has no `enable_thinking` switch. The reasoning policy must replace the direct JSON-only system instruction with a prospectively fixed compatible instruction, requiring the original typed answer JSON inside the single final answer block. Do not train a bare JSON target immediately after a thinking prompt. Freeze a complete-response parser requiring nonempty completed thought, one completed answer block with valid typed JSON, and native EOS. Preserve malformed and truncated traces. The earlier [4096-token experiment](NATIVE_AGGREGATION_REASONING_LONG_RESULTS.md) demonstrates why512-token truncation cannot diagnose unrestricted reasoning quality; its exploratory6/36 result is not method evidence.

Aggregation is computed from the vision features once, without autoregressively generated aggregation tokens. The ordinary decoder then reads the memory through its initial cold prefix and later native autoregressive cache. This leaves subsequent reasoning tokens free to compose with that representation. It does not require reusing a detached prefix across independent questions; the failed443978 reuse check remains a separate unresolved result.

Before a reasoning run, separately verify Cosmos pixel/feature scattering, initial language-adapter parity, memory gradients, final checkpoint restoration, actual EOS handling and cold long-cache positions. The existing NF4/BF16-compute storage and unrestricted greedy/repetition-penalty1 policy are experimental choices, distinct from the card's BF16 test configuration and stored generation settings. The configured128000-position context limit does not establish measured long-generation feasibility. The current memory runtime explicitly caps generation at50 and retains every full-vocabulary raw head vector; it must not be silently repurposed for4096-token experiments. A new long-generation implementation needs a prospective storage and audit budget. One full FP32 vocabulary-logit copy alone is about2.49GB at4096 tokens; an additional FP16 head capture is about1.25GB, before repeated list/stack copies and growing masks. Preserve every emitted ID and compact cache/position ownership records, while preselecting a bounded numerical head-replay subset before predictions. Avoid redundant full vectors and quadratic saved masks. Declare the sample's coverage; do not claim exhaustive numerical replay from sampled rows. Measure inclusive capture/publication cost, actual completion lengths and at least one long-cache case before releasing a benchmark-scale run.

The composition questions are paired within Cosmos: does memory improve aggregation relative to ordinary input under reasoning, and does reasoning improve over the same memory's direct policy? Report both effects, absolute accuracy, completion and measured total cost. A primary4096-token result can be accompanied by prospectively fixed censored prefixes from the same trajectory, without rerunning or selecting a favorable budget. A positive original Qwen pilot first motivates new-world/two-seed confirmation; the small historically used official test does not alone establish the broader objective. Any stronger claim about content-dependent mass also needs the separately planned item-count-only control.
