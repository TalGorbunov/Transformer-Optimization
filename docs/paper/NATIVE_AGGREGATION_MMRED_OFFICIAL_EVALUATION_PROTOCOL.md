# Original MMReD: prospective fixed-checkpoint evaluation protocol

Status: prospective, unfrozen analysis specification. This document fixes the questions, scoring and interpretation before validation/test predictions from the three pilot fits. It authorizes no computation or additional fit. The [pilot design](NATIVE_AGGREGATION_MMRED_OFFICIAL_PILOT_DESIGN.md), pinned original-data recovery and unchanged strict [answer parser](../../scripts/mmred_official_answer.py) define the underlying experiment.

Evaluate all three final checkpoints—ordinary joint images, normalized memory and mass memory—on all 400 validation rows and all 600 selected test rows, regardless of training diagnostics or the competence screens below. Validation has 50 rows per task at each of N8/N16; test has 50 rows per task at each of N8/N16/N32. Thus each arm has 1,000 trajectories, with 3,000 total. Preserve the original four tasks, questions, worlds, golds and manifest order. N64/N128 remain outside this release. Use the fixed final three-epoch checkpoint only; no validation-based checkpoint selection, refitting, prompt change, retries or extra samples. A missing checkpoint, incomplete run or failed software audit is reported as incomplete/invalid evidence, never an efficacy-based reason to omit an arm. All available outcomes remain published.

Use one cold native prefix for each question, the same declared processor/image inputs and native greedy generation, at most 50 new tokens through native EOS 151645 or 151643. Independent-question prefix reuse remains outside this pilot after the preserved cache-parity failure. Primary correctness requires the complete response to parse as exactly one typed JSON answer object, equal the original gold, and finish with native EOS. Remove only the final EOS for text decoding; retain every other token, including special tokens. Wrong answers, invalid JSON and truncated responses all count as incorrect in the fixed denominator. Publish format validity, semantic match and EOS completion separately without substituting them for primary correctness. Actual native GPU emitted IDs determine the score; the independently declared CPU numerical audit does not rewrite predictions.

For each task/length/panel/arm, report correct count, denominator and accuracy. The primary aggregation score is the equal-weight macro of `spend_together` and `where_spend`; `char_at_frame` is the retrieval control and `steps_in_room` the count control. Compute differences on unrounded accuracies, in percentage points. The single primary contrast is mass minus ordinary on the test N32 aggregation macro. Mass minus normalized and normalized minus ordinary are secondary contrasts. Report all three contrasts, each task separately and each length separately, including unfavorable results.

Use the recovery's existing `source_identity.world_sha256` for paired clustering. Its question-free canonical world is the full ordered sequence of five-person room-index tuples: people in Daniel/John/Mary/Michael/Sandra order, rooms indexed Bathroom/Bedroom/Garden/Hallway/Kitchen/Office. The pinned recovery validates step IDs 1 through N before hashing that sequence as canonical JSON. Therefore every frame and its order is retained; room occupant-list order, question, answer, task and record ID do not alter the fingerprint. Do not replace this identity with a prefix, rendered-PNG, question or answer hash. Preserve every original row and its multiplicity; repeated worlds are clustered, not deduplicated. Show unique-world counts, repeated-world group sizes, task-presence patterns and recorded split/prefix overlaps.

The exact paired bootstrap is as follows; its implementation must be reviewed and frozen before outcomes are used.

1. An analysis is identified by panel, selected length or lengths, and task set. The primary analysis uses test/N32/two primary tasks. Additional prespecified analyses use the same two-task set at N8 and N16, each of the four singleton task sets at every available panel/length, and pooled validation over N8/N16 for the two-task and singleton sets. Within each analysis, retain only its rows and group by the full world fingerprint. Keep every selected row of a world together, including the rare world occurring under both primary tasks.
2. Stratify whole clusters by N and the sorted set of selected task types present in that world. For the primary analysis the three possible task patterns are spend_together only, where_spend only, and both. Never resample two tasks of the same world separately within that analysis. Empty strata are omitted. Sort strata by N then their tuple of task names; sort clusters within each stratum by fingerprint.
3. For each analysis instantiate Python's standard-library `random.Random(24)` once. Generate 10,000 replicates with this advancing generator. For each replicate visit strata in the fixed order and, for a stratum of m clusters, draw m indices with replacement using `rng.randrange(m)`. Each selected cluster contributes all its original rows with its sampled multiplicity. Use exactly the same draws for every arm and every contrast in that analysis; do not reset the generator per arm or replicate. Reinitialize it only for the next prespecified analysis.
4. In each replicate, calculate each task's accuracy as its multiplicity-weighted correct total divided by its multiplicity-weighted row total. The aggregation macro is the arithmetic mean of the two task accuracies, even if resampling changes their relative row counts. Compute paired arm differences from these scores. No row is dropped because of an error, malformed response or truncation.
5. Use two-sided 95% percentile intervals, with endpoints at probabilities .025 and .975 using linear-interpolated empirical quantiles (type 7): for sorted valuesv of length B=10,000, h=(B−1)p, j=floor(h), and q(p)=v[j]+(h−j)(v[j+1]−v[j]). Save the cluster membership, ordering, seed, replicate count, implementation/package versions, replicate statistics and unrounded endpoints. No BCa correction, redraw after an unfavorable interval or alternative interval selection is allowed. Degenerate intervals or few clusters are disclosed.

Report these intervals for every arm's task and macro accuracy and all prespecified paired contrasts. The primary mass-minus-ordinary interval is the only inferential contrast used in the pilot qualification rule. All other intervals are descriptive, without a simultaneous-coverage or multiplicity-adjusted significance claim. Exact-world clustering does not remove dependence from shared shorter prefixes or historical benchmark use; those limitations remain explicit.

The ordinary baseline competence screen uses pooled validation: retrieval at least 80/100 and each of the two primary aggregation tasks at least 50/100. Report N8 and N16 separately, especially the N16 aggregation results; passing the pooled screen is not evidence of N32 competence. Count-control performance at least 50/100 is a descriptive reference, not an additional competence gate. Failure of the competence screen leaves attribution to better aggregation unresolved; it never stops evaluation or hides a memory advantage.

A promising mass-specific N32 pilot requires an interpretable ordinary baseline under that screen and all of the following prespecified point-estimate/interval heuristics:

- Mass aggregation macro at N32 is at least 60%, exceeds ordinary by at least 10 percentage points and exceeds normalized by at least 5 percentage points.
- The paired 95% bootstrap lower endpoint for the primary N32 mass-minus-ordinary macro contrast is strictly greater than zero.
- Each N32 primary task's mass-minus-ordinary point contrast is nonnegative.
- At N8 and at N16 separately, the primary two-task mass macro falls no more than 5 percentage points below ordinary.
- For each N32 control task separately, mass falls no more than 5 percentage points below ordinary.

These are prioritization heuristics, not estimated optimal cutoffs or evidence of five-point noninferiority. Report which individual conditions pass rather than only a combined label. N32 has only 100 primary questions, 50 per task: five macro points correspond to five net correct answers, and paired uncertainty can be wide. At a 50-row control denominator, a nominal five-point drop permits two additional errors (four points); three are six points and fail the heuristic. The safety conditions use unrounded point differences, not a confidence claim.

The official test has historical use and is exploratory; it is not a fresh confirmation set. A qualified pilot motivates a separately frozen follow-up on new full worlds with two independent training seeds and a predeclared sample size/uncertainty target. No pilot result alone establishes a general aggregation improvement, useful reasoning-model composition or the user's broader aggregation objective. Publish all raw strata, including most/least question variants, answer priors, zero/nonzero counts and retrieval positions, as descriptive analyses without promoting a favorable stratum to the primary result.

If normalized memory improves over ordinary but mass does not improve over normalized, the supported hypothesis is about this compressed representation/readout under the fixed training recipe, not a special benefit of mass. Normalized means already preserve relative frequencies; the log-mass channel also contains item-count and score-scale information. If a mass advantage replicates, a future separately declared item-count-only channel control is needed before attributing it to content-dependent attention mass. Do not add that control or a memory-size/loss/initialization sweep after inspecting this pilot. If neither compressed arm improves primary aggregation while preserving retrieval with a competent ordinary baseline, stop this configuration. Failed competence or inconclusive intervals yield unresolved evidence, not an aggregation success.

Report adapter and active memory parameters, allocated and peak memory, all shared vision preparation, training work, generated tokens and measured cold inference cost for all three arms. Equal question exposure and adapter scope do not imply equal parameters or compute. A useful aggregation-accuracy gain at matched total measured inference budget, independent-question preservation, relevant-load controls distinct from rendered-Step/ordinal changes, and native plain/reasoning replication remain separate requirements beyond this pilot. Cheaper noninferiority alone is an efficiency result, and this cold evaluation makes no independent-question cache-reuse claim.

The combined execution is one CPU-only Slurm report, at most 1,800 seconds with four cores and 16GiB, consuming three completed, numerically passed independent evaluation audits. It performs no tensor/head/core/model replay and adds no GPU work. The audits provide source-ordered lean prediction records and references to exact original rows, final checkpoints, feature provenance and measured work. The combined reporter independently joins all 1,000 rows across arms and checks the strict parsed score against retained text/IDs; numerical completion is its only eligibility condition. The original recovery identity is flattened as world_sha256 in the rendered-row manifest; require equality to that bound identity, not a newly question-dependent group key. Reconstruct the canonical sequence identity from each bound original renderer record without opening images.

Run exactly 30 data bootstrap analyses: validation N8, N16 and pooled N8/N16, and test N8, N16 and N32, each crossed with four singleton tasks and the two-primary-task set. Save unrounded binary64 replicate arrays under the designated DATA root, with column names, shape/dtype and file hashes; save every cluster's source-row membership, task pattern and sampling order. Repository artifacts contain score/interval tables, all individual heuristic flags, descriptive strata and answer priors, audit/source/input hashes, costs and a human-readable report. Export a standalone PDF and PNG with three test-length panels (primary macro, spend_together, where_spend), three arm legends and the declared percentile intervals. Matplotlib runs only in the CPU job; plots cannot change the calculations or select favorable panels. Source-only preparation runs no bootstrap or plotting.

Descriptive question strata use only exact original text, answer type/gold and bound sequence metadata. Recognize most/least and requested retrieval frame only with an anchored match to the original known question forms and canonical names/range; otherwise label unclassified. Publish exact answer priors, numeric zero/nonzero, requested frame and relative frame position when recognized. No generated explanation, answer-conditioned relabeling or retrospective bin search is permitted. Retain source file/row/cell indices and hashes. Small predeclared software fixtures cover deterministic bootstrap draws, type-7 quantiles, correlated duplicate-world/two-task membership and exact score/heuristic boundaries; they are separately logged and run only in this CPU allocation.

Cost tables carry the independently audited training exposure and elapsed/resource records, per-arm observed cold generation including capture/publication overhead, output-token counts and memory. Label those timings instrumented cold latency, not production latency or FLOPs. Disclose shared feature construction once in the experiment ledger, and include one copy of its measured work for each arm's standalone deployment accounting; do not divide that cost by three or claim observed threefold deployment cost. Preserve preparation, software profiling and audit costs as separate stages where records exist. No missing timing is replaced by a guessed measurement. Publish the completed report even when all efficacy heuristics fail, and do not release another experiment from its label alone.
