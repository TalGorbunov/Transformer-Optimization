# Resource-continuation handoff for the fixed official pilot statistics

This new report changes only provenance and cost plumbing after the original evaluation array 444052 stopped at its resource gate. The original allocations used 33, 32 and 33 GPU-seconds for ordinary, normalized and mass, respectively: 98 seconds total. Each produced exactly the first fixed N8, N16 and N32 world and no later predictions. Their failures and false 10,800-second forecasts remain preserved. One separately reviewed continuation evaluates the remaining 997 worlds per arm, with a 14,340-second new-allocation cap and a 14,400-second old-plus-new cap per arm. This report neither authorizes that execution nor changes its models or decisions.

The scientific specification remains the exact frozen [evaluation protocol](NATIVE_AGGREGATION_MMRED_OFFICIAL_EVALUATION_PROTOCOL.md), SHA256 `e22eae44ada348fc919830524b86d5cbea755a9a17b851b02e0e049d1e0cd409`. The original combined reporter, SHA256 `7f32ab89c8012fab358e91d07fbec2990c87a264a2e3ea69711c9387dbdfe6f5`, is inherited unchanged. The new entry point imports and calls its bootstrap, type-7 quantiles, exact Fraction qualification rules, world reconstruction, strict scoring helpers, descriptive strata, plotting, cost base table and software fixtures directly. It does not modify that module's globals or copy/change its statistical functions. The original three-source release and all 232 ancestors are hash-bound, together with the new independently audited continuation closure.

Inputs are all three completed numerical continuation audits, including every one of the original 1,000 source-ordered predictions per arm. Numerical completion is required; accuracy is never an eligibility condition. Preserve all 400 validation and 600 test rows, the same final 1,500-update checkpoints, typed JSON plus native EOS, greedy 50-token limit, original worlds/golds, and shared feature identities. Independently check the exact base prediction fields against the three original durable JSON records and their prefix inventory. Require the original resource-failure type/message and configuration, retain their descriptors, and check that neither their raw packet paths/hashes nor IDs, text, score, seconds or peaks changed. Raw tensor payloads are not reopened by this combined report; the per-arm numerical auditors verify them.

Derive the three prefix indices as the first original row at N8, N16 and N32, in that order. All other indices occur exactly once in source order. Every prediction has `origin`, `source_run` and `source_execution_index`; the former three must refer to the original run and indices 0–2, and the latter 997 to the continuation run and indices 0–996. Hash-bind original failure/configuration/request/prefix-prediction/prefix-projection metadata, the audited continuation lineage, and the new combined predictions. Save a separate per-arm origin inventory. Imported outcomes are not regenerated, rescored into a different policy, or used twice. Independent strict-score recomputation is an audit of the retained text/IDs, not a replacement of the native output.

Run exactly the same 30 analyses and 10,000 paired full-world bootstrap replicates per analysis, with the same advancing Random(24), sorted length/task-pattern strata, task-weighted denominators, equal primary-task macro, shared arm draws and type-7 95% intervals. All fixed thresholds and heuristic qualifications are unchanged. Publish all outcomes, including valid negative results. Save unrounded replicate arrays under DATA, cluster/source inventories, score and interval tables, answer priors and original-question strata, all condition flags, and the same three-panel standalone PDF/PNG. Historical-test, multiplicity, precision and interpretation caveats are unchanged.

Retain the original cost helper's combined 1,000-trajectory sums, which already include the three imported timings exactly once. Append per-arm original, continuation and cumulative GPU allocation seconds, their sum across arms, and the original 98-second subtotal. Allocation totals include setup and overhead and are not added again to the trajectory sums. Report original-three and new-997 trajectory seconds and token counts separately, alongside their combined totals. Shared feature construction remains charged once experimentally and once for each standalone deployment arm. Preserve both old and new setup/elapsed components from the independent audit. All timings remain instrumented measurements, not production latency or FLOPs. Original per-layer counters were not saved; expose the auditor's explicit coverage limitation rather than infer observed counts from expectations.

The new report is one CPU-only Slurm job capped at 1,800 seconds, four cores and 16 GiB. It adds no GPU, model, core, head, fitting or tensor replay. Small lineage fixtures separately verify exact first-per-length partitioning, mutation and origin rejection, the 33/32/33 allocation ledger and cumulative cap rejection; the frozen statistical fixtures run unchanged. No numerical fixtures or plotting run on login. Own sources are this document, `scripts/report_mmred_official_pilot_continuation.py` and `slurm/mmred_official_pilot_continuation_report.sbatch`. All originals remain immutable. Successful publication is last and does not release further work.
