# Independent audit of the original MMReD final-checkpoint evaluation

Status: draft, unreleased. This is a computational audit of each of the three unconditional evaluations specified by the [prospective evaluation protocol](NATIVE_AGGREGATION_MMRED_OFFICIAL_EVALUATION_PROTOCOL.md). It does not select models, change predictions, authorize another fit or make a statistical qualification decision.

Each arm has one CPU allocation of at most 7,200 seconds, four cores and 16 GiB. Audit all 1,000 original rows: 400 validation questions at N8/N16 and 600 test questions at N8/N16/N32, with 50 rows in every panel/length/task cell. Require the exact source cohort, fixed final update-1500 checkpoint, passed independent training audit and complete evaluation artifacts. Correctness never determines inclusion. An incomplete producer or numerical audit remains incomplete or failed, and its available evidence is preserved.

The auditor reads saved CPU tensors only. It makes no decoder, vision, model, generation, fitting, backward or optimizer calls. Every emitted native query is replayed once through the bound original FP16 norm and vocabulary head at the actual selected one-row shape. There are at most 50,000 CPU norm/head calls and rows per arm, corresponding to 1,000 trajectories of at most 50 output tokens. Save each actual CPU replay before applying the unchanged full-vocabulary total-variation bound of 0.02. CPU/GPU argmax disagreements are descriptive; native GPU emitted IDs alone determine efficacy. Require the captured native normalized query to equal the actual head input exactly, the actual native vector to equal its saved raw generation vector exactly, and each generated ID to be its raw native argmax.

For normalized and mass memory, independently reconstruct all 1,000 actual memories in FP64 from the bound native feature bytes, merged-raster coordinates and final FP32 memory parameters. Reuse the frozen independent formula and the prospective absolute and relative tolerances of 2e-4. Save the reference tensors and each field discrepancy. Separately require exact ownership of the actual FP32 memory output, its single native FP16 cast and the actual input embedding identity. The ordinary arm has no memory reconstruction. None of these comparisons invokes the trained memory module or the language decoder.

Audit complete cold trajectories: unchanged official system/question text and chat boundaries, original native mRoPE for ordinary features, explicit four-axis sequential positions for memory, own generated-token histories, masks, cache positions and lengths, full norm versus selected head shapes, native EOS IDs 151645/151643, the fixed 50-token cap, restored mutable rope state and removed hooks. Bind every packet to its source index/SID, panel, length, task, compact input, exact feature metadata, native identity and final parameter state. Independent-question prefix reuse remains unqualified after the preserved original cache-parity failure.

Use the unchanged strict typed-JSON parser. Decode by removing only the final native EOS; retain every other token and use `skip_special_tokens=False` and `clean_up_tokenization_spaces=False`. Independently check the parser fixtures and decoded-text ownership. Invalid format, wrong answers and truncation remain in the fixed denominators. Publish format validity, semantic match, completion and primary correctness separately. A valid negative evaluation can pass this computational audit.

Collect every scheduled numerical result before the final numerical gate. Ownership, source, shape or missing-artifact errors may stop early and must retain the current audit progress. Save one small numerical audit record per scene and a source-ordered `predictions.json` with the native IDs, strict score, original record identifiers, raw-packet reference, complete measured generation time and memory peaks. Publish exact original-row, feature-stage, checkpoint, producer, source and accounting bindings. The separate paired statistical report consumes the three complete numerical audits and their compact predictions; it does not read or rescore native head arrays.

Audit recorded one-call-per-output-token and all 28 decoder-layer counts, zero evaluation vision/backward/optimizer calls, the producer's prospective resource projection and actual bounded Slurm allocation. Shared vision feature preparation is reported separately. Timing projections are empirical, not latency guarantees; equal question exposure does not mean equal parameters or compute. Preserve all original profile failure flags and do not turn this audit into an automatic release for N64/N128, cache reuse or follow-up training.

Raw trajectories can occupy roughly 16–20 GB per arm at typical short JSON answers and approach 100 GB per arm at the 50-token cap. CPU replay and FP64 reference tensors remain under designated data roots; no coefficients, checkpoints or large tensors are written into the repository. These estimates describe storage planning rather than a new numerical or accuracy gate.

The public verification handoff checks current and archived source identities, the immutable manifests' own hashes, summary/analysis, compact predictions, original rows and stage/final-checkpoint references. It deliberately does not rehash all large raw head files again: `raw_files_rehashed_in_handoff=False`, while `raw_inputs_verified_in_cpu_audit=True` records that the completed CPU audit verified every actual consumed raw, feature and checkpoint packet. A partial or failed audit cannot use this successful handoff.
