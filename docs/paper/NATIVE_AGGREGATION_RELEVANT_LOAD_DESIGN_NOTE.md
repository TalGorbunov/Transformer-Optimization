# Measuring relevant aggregation load separately from distraction

This is a design note, not an experiment release. Current models fail the216-context training screen. The unused confirmation and all native/extrapolation gates remain held. No data is generated under this note.

The existing identity-join N16/32/64 panels preserve six relevant frames and add irrelevant-room images. They measure resistance to distraction, position changes and longer contexts. They do not increase the number of relevant identities, distinct bindings or independent relations that must be retained. Passing them would be useful but insufficient evidence of increased aggregation bandwidth.

A candidate load assay can retain the MMReD images and question while varying the number K of relevant candidate identities: K in {3,5,7,9}. Each candidate appears in two relevant frames. One target appears once in each requested room; every other candidate appears twice in exactly one room, with half those candidates in each room. For odd K this gives2K relevant frames, identical per-person counts2 and identical requested-room countsK. Rotating the target within matched scenes changes the answer while preserving those marginals. All identities and rooms must appear during training; larger K should introduce a combinatorial load increase rather than new visual classes.

Cross K with a separately controlled number D of irrelevant-room frames. Then total length is N=2K+D. No design can hold N fixed while varying K and D independently: the factorial grid and selected matched-N comparisons serve different purposes and should both be reported. Repeated appearances alone are not a larger number of independent bindings; K is the relevant change. Rendering positions, Step indices, room orientation, identity frequency and background composition require explicit balancing. Training on small K and testing larger K would require a newly frozen split that controls question and pair coverage; it cannot silently reuse the current trio-based confirmation as a larger-load test.

A subsequent multi-relation assay would vary the number of independently requested relations on one scene set and require every natural answer. That tests preservation of multiple answers more directly than a single identity among more candidates. It also changes output length and prefix distributions, so it needs its own training and evaluation protocol. A short-answer adapter has not yet demonstrated benefit on reasoning prefixes merely because its architecture can run at every token.

A convincing result would compare accuracy as relevant load increases at fixed adapter rank and numerical precision, report complete natural answers, and include actual compute costs. The ordinary joint model, an adaptation-matched baseline and a reasoning-token baseline answer different efficiency questions. Count all N+1 parallel streams, vision prefills, generated tokens, latency and memory. A fixed final-normalization residual outside KV can affect later steps through generated prefixes; this is not yet evidence of useful latent or reasoning composition.

This assay should be registered only after a visual method passes native whole-answer and untouched fresh-support checks. None of its settings should be selected from outcomes on the current untouched confirmation.
