# V18 saved-state diagnosis

The four main fits are fixed and running. This proposed CPU analysis uses their saved artifacts after the independent report passes. It adds no model call, head call, intervention, fit, accuracy threshold or outcome-based selection. Analyze all four models and all272 fresh scenes, retaining failures. Its purpose is to distinguish errors in semantic selection, vector aggregation and native answer generation.

The independent report already verifies each original gate, complete probability normalization, unchanged reuse at every generated position, all-coordinate multiplication, closed coordinates, native raw decoding, parameter identity and every denominator. This analysis should bind that report and its artifacts rather than repeat expensive head replay or claim a new correctness gate.

For every scene, use only the original empty-prefix query for comparisons across lengths. Later generated prefixes can differ, so later trajectories support error descriptions but do not provide matched hidden-state counterfactuals.

1. **Selection:** count false-negative and false-positive original gates, positive gate range and total negative gate mass by N/K and physical Step<=16/>16. Record positive attenuation A=sum_pos(1-g), negative leakage L=sum_neg(g), and off-{0,1} vocabulary mass. Verify sum(g)-K=L-A without fitting a threshold. Use the gate actually applied by each mode for vector accounting. Ground truth is used only in this analysis; no gate or answer is changed.
2. **Contributions:** in FP64, partition saved messages into positive sum P and negative sum Z; report their norms, cosine when defined, and the corresponding frozen-Wagg projections. Verify P+Z equals the direct sum of saved messages. Compare this with the saved FP32 aggregate descriptively. If all native negative gates are closed, Z must be exactly zero, but that does not imply a correct learned positive payload or answer decoder.
3. **Paired length drift:** use the manifest's semantic N32-to-N64 parent mapping, retaining rerendered Step-label changes. Report query drift and positive-message drift. For each matched positive item, decompose g64*u64 - g32*u32 as (g64-g32)*u32 + g64*(u64-u32), where u is the saved bounded payload. Sum the two terms and verify the FP64 identity. This separates changed gate weights from changed contextual payloads algebraically; it does not identify causal accuracy mediation. Report added-negative contributions separately.
4. **Native answer failures:** copy the verified first-token, full-answer, parse, EOS and truncation outcomes. Compare the saved unfused original global logits with the saved fused first-step logits at that same state, including native argmax and correct-first-token margin; no new head call is needed. Classify the first wrong target position only while the executed prefix agrees with the gold target prefix. Distinguish a wrong first numeral token, a correct first numeral token followed by the wrong complete number, and output-format failure. Shared leading digits make first-token accuracy an insufficient success criterion.

No diagnostic statistic changes the V18 primary or practical decision. If selection is correct but errors remain, the next experiment should target payload invariance or native decoding rather than tune the gate. If selection fails, characterize that failure before training another aggregation core. If practical accuracy passes, a fresh value-holdout or task-transfer experiment is more informative than another seed or hyperparameter sweep.

This is prospective analysis design only. A small independently reviewed script, bound inputs, numerical identity checks and a CPU Slurm cap are required before execution.
