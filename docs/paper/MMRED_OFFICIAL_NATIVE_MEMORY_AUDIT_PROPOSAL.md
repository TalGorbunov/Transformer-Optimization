# Independent CPU audit of the original-MMReD native-memory profile

This is a software and numerical audit of one separately frozen, completed three-arm profile, including a complete profile that failed only its final numerical parity gate. It does not score the eight software cases for benchmark efficacy, choose an architecture, change a checkpoint, or release a full fit or validation/test inference. A valid audit of a reproduced negative result can complete successfully: top-level passed refers to the CPU audit, while original_profile_passed, cache_parity_passed, cold_training_components_passed and combined_software_parity_passed remain explicit separate fields. Reproducing an original cache failure does not make that profile pass or change its .02 threshold. CPU reconstruction, replay, CE, provenance and accounting failures still fail this audit. No route or fit is automatically qualified.

The producer, its passed eight-case CPU preparation and core check, every inherited source, actual native model identity, initial and intermediate parameter packets, final diagnostic checkpoints, source copies, raw captures, and saved allocation record are bound by exact hashes. For a complete failed profile lacking final summary/artifacts publication, bind config, analysis, the preserved failure, pre-execution source release, and a newly constructed exact inventory of every available file in its registered output/data/checkpoint directories. Earlier failed preparation attempts remain preserved in the preparation ancestry. Only the profile's original training cases and its explicitly transferred question strings enter this audit.

Use one CPU Slurm allocation with four cores, 16 GiB, and a 1,800-second cap. All tensor loading and arithmetic occur there. The auditor never calls the visual encoder, language decoder, memory core, optimizer, or backward. It may call only the frozen native final norm and vocabulary head for the predetermined replay inventory. No additional GPU job is authorized.

The profile has eight question-free vision extractions; four initial pixel-versus-feature teacher calls at N1/N16; sixteen forward/backward microcalls and two optimizer updates for each of ordinary, normalized-memory and mass-memory; four before/after checkpoint teacher calls per arm; five ordinary natural trajectories at N1/2/4/8/16; and twelve natural trajectories for each memory arm, consisting of four cold, four independently forked, and four reverse-order questions over the same N16 collection. Two extra memory prefix decoder calls are headless. Its maximum is 1,514 conditional-model/head calls, 1,516 decoder/norm calls, ten vision calls, 48 backwards and six optimizer updates. The auditor reconstructs the actual inventory from records, including all 28 decoder-layer counts.

CPU head replay covers all four initial parity teacher examples, all twelve checkpoint teacher examples, and only the first and last training microcall in each arm: step1/index0 and step2/index7. These are 22 teacher examples with their complete, CPU-derived JSON-plus-EOS target lengths. Replay every actual selected query in all 29 natural trajectories, each with the original maximum of 50 tokens and native EOS IDs 151645/151643. The conservative CPU limit is 1,472 head calls and 2,550 rows; exact counts are 22 plus actual natural output tokens, and the fixed teacher target-length sum plus those tokens. No accuracy-dependent sample is allowed. All 64 saved teacher calls, including all 48 training calls, retain a direct FP64 reconstruction of every position CE and its mean from the actual GPU full-vocabulary logits; both absolute discrepancies must be at most 2e-6. No training gradient is reexecuted.

For every captured memory computation—32 training, eight checkpoint and two prefix cases—independently reconstruct the actual 32-slot readout from saved native FP16 post-merger features, global frame/raster coordinates, and the exact FP32 parameter state owning that call. Arithmetic is FP64: the independently generated 24 positional features, key-only RMS with epsilon1e-6, fixed 128-wide key projection and score scaling, direct softmax mean, log partition, optional mass feature, and the final native-width tokens. Compare the saved FP32 mean, log mass, mass feature and tokens with fixed elementwise tolerance atol=2e-4 and rtol=2e-4. Record errors and complete reference tensors. This is numerical fidelity, not exact arithmetic or a claim that finite moments preserve arbitrary relations. Any reuse of a computed reference must have identical bound feature, coordinate, parameter and arm identities.

Independently verify that the actual memory tokens undergo exactly the recorded FP32-to-FP16 cast, that cached prefix embeddings and question-independent boundaries refer to the same memory, and that the actual normalized native query equals the actual head input exactly. Native CPU replay uses the exact original FP16 norm/head weights and the observed selected-row batch shape. Save each replay before comparison. Require full-vocabulary TV at most .02. CPU/GPU argmax disagreements are descriptive; actual GPU-generated IDs define all stopping and same-runtime parity checks. No efficacy score is produced.

Independently reconstruct initial pixel/feature and trained checkpoint exact GPU parity. Every cold/split pair must retain identical generated IDs and TV at most .02; every split/reverse pair must have identical IDs and bit-identical raw logits. Check all question/answer histories, native masks, explicit positions, cache lengths, fixed prefixes and their 28-layer K/V identities, absence of question pixels on a cached branch, frozen model/configuration state, and cleanup. The original-image path retains native mRoPE; compressed slots use the predeclared sequential four-axis positions and zero delta. These finite software comparisons do not establish equality for another fitted endpoint or another collection.

Collect all scheduled numerical results and save reference/replay tensors, outcomes without efficacy scores, counters, timing reconstruction and allocation evidence before enforcing the CPU numerical gate. Independently reproduce the original combined GPU gate and preserve its outcome, including any failed cold/split comparison. The separate cold/training component flag requires all CPU numerical checks and exact pixel/feature and checkpoint comparisons; the cache component retains every cold/split and reverse-order comparison unchanged. Structural ownership violations may stop immediately with retained partial evidence. Reconstruct the producer's empirical forecasts from every fixed timing observation, including measured load/transfer/observation/publication work. Shared frozen vision preparation is counted once; three epochs of 4,000 training pairs require 12,000 microcalls and 1,500 optimizer steps per arm. These training-only forecasts exclude the separately identified 100 diagnostic generations and all validation/test work. The eight timing cases cover fixed length strata, not the full 4,000-example prompt/teacher-width envelope; that full prepared envelope and the omitted diagnostic-generation budget require a later separate resource review. These forecasts are neither latency guarantees nor complete execution-release budgets. A passed audit always retains no_full_fit_release=True.

Tiny CPU fixtures cover the independent uniform-score mean/log-mass result and the fixed replay/call arithmetic. They make no native head or model calls. Source and proposal identities are frozen before this audit; no tolerance, replay subset, checkpoint, task or resource cap is changed after observing results.
