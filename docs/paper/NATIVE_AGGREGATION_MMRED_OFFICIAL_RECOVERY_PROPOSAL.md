# Original MMReD Vision: pinned data recovery and CPU audit

This stage recovers the original benchmark before any reusable-memory experiment. It acquires the Hugging Face dataset `ef1e43ce/mmred` at revision `d7963ebac13621dd1105e7596d8ed4a4c442119a` and the upstream `https://github.com/Fr0do/mmred.git` source at commit `56c6ee7041d539c7273d42d5a6c4c5e922015e40`. Both identities are fixed before acquisition. Bounded metadata-only API reads before source freeze verified66 HF files totaling82,014,317 bytes and the exact upstream tree `8faf4592c479b37fb3a675ee35a97c3f30b06ac0` with96 source blobs totaling629,906 bytes, including the original renderer. The CPU acquisition rechecks these identities and sizes. Download into a new job directory beneath `/mnt/data/gabriele/gnn_transformer/mmred_official`; preserve all old datasets and outputs. Inspect actual remote file inventory and declared sizes before downloading. The complete HF snapshot must be at most256MiB. Fetch upstream with a120-second timeout, verify the exact detached commit and clean tracked checkout, and require its resulting repository to be at most128MiB. This latter size check is after fetch; it is not a hard network-byte limiter. Save actual sizes, file hashes, package/git versions and source revisions. A missing revision or different layout is a retained acquisition failure, not permission to substitute another source.

The expected dataset contains18 configuration/split cells and39,600 rows: N1/2/4/8/16 each have4,800 train and1,200 val/test rows; N32/64/128 have1,200 test rows only. Each cell has exactly24 qtypes,200 per training type and50 per validation/test type. Read every original Arrow row on CPU, preserve the original question, answer, ID and order, parse all state frames, and validate the official five-person/six-room vocabulary, complete character ownership, contiguous steps and exactly one person's room changing per transition. Recompute all24 answers using the separately hashed existing adapter. Retain every mismatch with row identity; finish the complete answer audit before deciding data-integrity success. No synthetic world or label replacement is allowed.

Compute full semantic world identities from the ordered sequence of person-to-room assignments, independent of question, qid and occupant-list order. Separately retain the exact parsed sequence identity. Inventory every repeated full world and exact leading-prefix match, with source cell and original row identities; do not expand matches into quadratic row-pair lists. Report full-world overlap across official splits and how many selected validation/test rows equal a selected training world. Short N1 has only6^5 assignments, so world repetition is possible. Overlap is evidence about the benchmark, not an acquisition failure or permission to silently change official splits. A successful recovery does not establish world-disjoint evaluation. Any later derived multiquestion panel must define its own world-group split without relabeling the official benchmark.

After the complete inventory/answer audit passes, freeze the original four-task pilot: `spend_together` and `where_spend` are primary aggregation tasks; `steps_in_room` is the scalar tally control; `char_at_frame` is the retrieval control. Keep all200 examples per type at each training N1/2/4/8/16 (4,000 rows), all50 per type at validation N8/N16 (400 rows), and all50 per type at test N8/16/32/64/128 (1,000 rows,200 per length). Preserve source order within each cell and ascending length across cells. N8/16 are the in-range benchmark, N32 the first extrapolation endpoint; N64/128 remain later held endpoints. Do not choose rows by answers, model scores, task difficulty or overlap. Keep original most/least variants and answer priors; publish their inventories. Emit renderer-compatible JSON plus an immutable ordered row manifest, source-row hashes and semantic identities. No image is rendered in this stage.

Recover and hash upstream renderer/generator source but never import or execute that downloaded source here. Extract the existing official JSON-answer system prompt from the hashed local evaluation source without importing its model dependencies. Preserve it as protocol metadata. The primary task is the original one-question-per-world benchmark; no added queries, reasoning targets, caption scans, answer-code oracle, model tokens, decoder inputs or statistics are created. Existing inspected official test results are historical benchmark use, so these rows are not advertised as untouched new confirmation.

Allow one600-second CPU Slurm allocation, four cores and16GiB. Network access and Arrow parsing happen only there; no package installation, image work, model/head/vision call, accelerator, training or inference is released. Source closure is the three new files (stager, proposal, wrapper) plus the two hashed existing adapter/protocol files. Tiny CPU-only fixtures cover world identity, occupant-order invariance, illegal duplicate ownership/transition rejection and within/across-split overlap accounting. Save inventory and partial audit files before failure; publish the passed summary last. The final plan remains `no_training_or_inference_release=True` regardless of overlap or data-integrity success.
