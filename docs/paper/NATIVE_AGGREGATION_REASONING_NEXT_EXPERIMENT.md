# Next Cosmos experiment: evidence access before composition

**Proposal only. No GPU release, preregistration, or efficacy claim.** This memo uses completed artifacts and does not inspect ongoing V10 outcomes. The objective is a native aggregation operation that remains useful at successive generated queries. The next experiment must distinguish improved answer readout from improved reasoning.

The frozen Cosmos 4096-token assay obtained 6/36 correct N32/N64 answers versus 4/36 direct, with four reasoning truncations and a paired interval touching zero. It establishes a weak baseline premise, not reliable reasoning-based counting. It used a fixed random branch and short generations. It establishes neither trained efficacy nor 4096-token parallel-cache feasibility. ## Two constraints that determine the design

The deployed branch changes the global state immediately before the final norm/head; it does not modify the backbone KV cache. Under teacher forcing, later inputs are supplied tokens. Consequently, answer-only CE supplies **no gradient through earlier thought-position branch outputs**. Earlier outputs matter during free generation through their discrete token choices. Turning on an answer-only-trained branch during thoughts is therefore an untrained intervention, not a fair composition test.

Furthermore, the current parallel global row is text-only. Disabling its branch before the answer removes image access from the thought generator. Local rows receiving the shared tokens do not send their evidence back until fusion is enabled. This is not ordinary native Cosmos visual reasoning.

A clean answer-phase-only online experiment would instead retain the ordinary **joint-image global row**, alongside N independent local rows. However, an ordinary N+1-row batch pads every local row to the long joint prompt: N64 produces 65 rows with the joint prompt width. KV storage and transformer work can grow dramatically, beyond merely processing the images twice. Profile 441994 does not validate this layout. Native packing, masks, positions, numerical behavior, peak memory and full-length cache growth require a new gate; no custom packing/cache shortcut should be assumed equivalent.

## Optional precursor: answer readout at fixed natural prefixes

An optional precursor avoids that unvalidated online expense; it is not a prerequisite for the matched online route below. Collect frozen **ordinary joint-image Cosmos** direct outputs and natural reasoning traces. Separately obtain local image/query states at each actual answer prefix. Combine these with the corresponding frozen joint global state and train the unchanged learned SUM/SiLU residual through the native norm/head. Backbone computation may be separate here: this is an **offline continuation diagnostic**, not one-forward deployment or free-running composition.

A bounded proposed pilot has 180 training scenes balanced over N8/N16 and K0–8, 36 fresh N16 development scenes, and 18 fresh test families, two per K0–8, extended N16→32→64. The ten N8/K8 training slots must reuse historically seen saturated contexts; all 54 possible question-conditioned contexts already entered earlier training. Bind their exact prior identities and make this the sole freshness exception. Every other new training, development and test context excludes all selected V1–V10 and prior reasoning data, with test also excluding current train/dev. This familiar-answer pilot remains separate from V10's full-support experiment. Preserve the same renderer, negative-frame law and original labels; recurring visual atoms are disclosed. This pilot concerns familiar answer support, not unseen integers or real-world transfer.

Use the pinned Cosmos compatibility checkpoint, its official reasoning system prompt, identical question wording, 392px images and the existing native quantized greedy policy. Direct cap32 and reasoning cap 4096 remain fixed. Generate each teacher trace once without supplied scratchpads. The precursor retains reasoning prefixes whenever the natural answer boundary is structurally present, regardless of answer correctness; report missing-boundary coverage. Train on full gold numeral, closing structure and EOS only after that boundary, alongside direct-answer prefixes. No test trace enters fitting or checkpoint selection.

On every test scene, compare residual ON/OFF continuations from identical direct or reasoning prefixes ending at the answer opener. Only this pre-answer prefix is fixed: generate every answer token freely and recompute states for that condition's actual emitted suffix. Never feed the original answer or gold answer tokens into test continuations. Missing boundaries, malformed outputs and truncations remain incorrect in all-example policy metrics; conditional readout metrics show their smaller denominators. A prospective screen is at least +5 percentage points on N32/N64 in both prefix conditions, with N16 degradation no greater than5 points. Use complete-family bootstrap intervals and report every K. This small screen identifies a useful readout candidate; ON/OFF is an intervention on a trained adapter, not an adaptation-budget-matched architecture comparison.

If this precursor fails, do not advance the same answer-readout hypothesis without explaining the failure. A genuine answer-phase-only online direct/free-reasoning 2×2 would be conditional on the joint-global software/resource gate above. Freeze the same trained adapter and cross residual OFF/answer-phase ON with direct/reasoning policy on **new** families. Before the answer boundary, reasoning traces should be identical across ON/OFF. Improvement there establishes answer-phase assistance after native visual reasoning, not improved thought computation.

## Preferred online route: matched full-trace supervision

The cleaner first online question retains the existing efficient text-only global layout and gives **both** conditions learned visual access at every token. First collect one natural frozen joint-image Cosmos trace per training scene, cap 4096, without supplied scratchpads. Retain only strictly completed, correct final answers for full-trace CE. Record every attempt and retention by N/K/question. A proposed pilot coverage gate is at least two retained traces in each represented N/K cell, frozen before collection; failure stops the stage rather than triggering sampling until correct or dropping difficult cells. Correct final counts do not certify intermediate statements.

Train matched models with the same direct-answer CE and the same retained full-trace CE, at all actual strict prefixes including thought tokens, answer structure and EOS. Add coefficient 1 direct-answer residual consistency only in the treatment; the control coefficient is 0. Direct prefixes retain identical frozen text-only global states within the registered pair, so the existing loss contract is valid. Never align unmatched thought prefixes. Fix the direct/trace mixture weights prospectively—proposed 1:1 of their respective scene-normalized token-mean losses—and use identical data weights, initialization, presentation order, optimizer and development selection across conditions. The K0–8 pilot tests familiar answers only; expanded support requires a separate declared inventory.

New Cosmos features are necessary for every actual model/prompt/prefix. Existing Qwen caches are ineligible. Both objectives must include thought-token supervision: answer-only CE cannot train their earlier branch outputs. Full-trace CE is behavior cloning at fixed prefixes, not gradient credit through sampled reasoning trajectories. Unequal retention across scene types and teacher mistakes remain limitations; freeze any weighting before model outcomes.

Cross the two trained objectives with direct 32 versus natural free-reasoning 4096, using **all-token fusion in all four cells**, fresh paired test families, the same checkpoints and two prospectively fixed training seeds. Both arms now share visual access, parameters and inference computation within each policy. The unmodified ordinary joint-image Cosmos baseline is descriptive: its architecture and work differ. The proposed screen requires treatment-minus-control OOD gain ≥5 points in both policies and no more than 5 points N16 loss, in each seed. Also require treatment reasoning to exceed its own direct accuracy before describing beneficial policy-level composition. Report paired-family uncertainty; a positive interaction is not required. A method gain under reasoning without a within-method reasoning gain establishes persistence, not an advantage from combining them.

This is preferable to a hybrid backend rewrite as the first online efficacy question, conditional on trace coverage, native long-cache checks and measured resources. It does **not** isolate whether the gain arose at thought positions or final answer positions. Do not use all-token versus answer-only activation on the text-only global model as a fair native-reasoning comparison: that also removes scene access during thoughts. Stronger causal claims need a later intervention that preserves visual access.

For the optional joint-global precursor, CE-only is the clean starting point and cannot demonstrate transfer of the old regularizer. Its paired global states differ. Comparing post-fusion g+delta with a fixed symmetric global-norm denominator could generalize consistency and reduce to the old residual difference when g is identical, but is a new objective requiring registration and a matched control.

## Read-only feasibility note: packing streams on one token axis

The installed stack is torch 2.8.0 and transformers 4.57.6. Its Qwen forward accepts explicit per-token 3-axis mRoPE; caller-supplied 4D masks pass through unchanged, and DynamicCache appends arbitrary query blocks. Thus a packed execution appears expressible, **not yet validated**. Concatenate each complete local prompt and the joint-image global prompt; concatenate their independently computed native positions and image grids in exactly the same order. Each token may attend only earlier/self tokens of its own stream. Decode appends one broadcast token per stream, with physical cache slots increasing globally but logical mRoPE increasing separately. Never infer logical positions from total packed cache length. Vision processes 2N images at prefill, none during decode. [Qwen implementation](../../.venv/lib/python3.10/site-packages/transformers/models/qwen2_5_vl/modeling_qwen2_5_vl.py); [mask handling](../../.venv/lib/python3.10/site-packages/transformers/masking_utils.py)

Stock generation appends one token per batch row, so batch-size-one packed streams need a new explicit decode loop and a fusion controller that gathers stream endpoints along the token axis. Existing controllers/generation audits cannot be reused unchanged. The global block must still receive every image, including when fusion is off. Native weights and attention equations can remain unchanged; packing, masks, backend behavior and numerical equivalence all require tests.

Let M=N+1, local lengths L_i, joint length G and P=G+sum L_i. Packed cache length after t steps is P+Mt; padded hybrid storage is M(G+t). FP16 cache bytes are 2×layers×KVheads×head_dim×2×length. At N64, using recorded local length 276 and an illustrative joint length 12,750, P≈30,414: the prefill mask alone is 0.86 GiB boolean or 1.72 GiB FP16. At 4096 steps, the packed native KV cache is about 15.84 GiB versus 58.48 GiB padded, before weights/workspace. These are shape estimates, not measured peaks.

Dense attention does not exploit the blocked zeros. Prefill work scales as P², whereas independently executing the streams costs G²+sum L_i². Packed decode costs M(P+Mt) score positions per head, versus P+Mt ideally. At the illustrative 4096 endpoint it has about 17.6 times the score positions of padded hybrid decode. The installed masked-SDPA adapter also expands 4 KV heads to 28 query heads, adding about 3.96 GiB temporary K/V storage per layer at that endpoint. Memory savings therefore do not imply a fast long-reasoning route. [Installed SDPA adapter](../../.venv/lib/python3.10/site-packages/transformers/integrations/sdpa_attention.py)

FlexAttention is a conditional backend candidate, not a ready fix. Torch exposes BlockMask and GQA, but the installed Qwen class inherits `_supports_flex_attn=False`, so the ordinary backend setter rejects it. The HF Flex adapter also expands K/V for 28 non-power-of-two query heads. Further, round-interleaved decode keys contain different streams every 65 tokens; the default 128-token sparse blocks and one 65-token query group leave essentially every block partially live. Merely substituting BlockMask does not remove dense decode waste. A validated stream-contiguous cache layout or other block strategy may be needed; smaller block sizes must satisfy actual Triton tile constraints. Changing the attention backend is a separately reviewed implementation change, not a new aggregation operator. [Installed Flex adapter](../../.venv/lib/python3.10/site-packages/transformers/integrations/flex_attention.py); [torch BlockMask/kernel API](../../.venv/lib/python3.10/site-packages/torch/nn/attention/flex_attention.py)

The minimum next gate is CPU-Slurm small-stream testing of masks, stream isolation, native token/image/position identities and cache retention, followed by a bounded GPU test against independent native executions on fixed software scenes. Test both zero and deterministic nonzero fusion, every stream at prefill/two forced decode steps, and global native-head replay; retain raw full-vocabulary differences and prospectively fixed numerical gates. Measure compilation separately, peak memory, sparse blocks actually visited and steady decode timing. A later 4096-step cache/runtime stress is indispensable before efficacy release. No compilation, model execution or installation was performed for this assessment. Dense packing is a useful correctness prototype; neither its speed nor the proposed sparse integration is established.
